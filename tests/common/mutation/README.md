# ミューテーションの清単：具体的な基準

AGENTS.md §14.5（ミュータントを加える基準）の具体的な基準。§14.2（予期する失敗）と §14.4（判定を変える場合）も合わせて読む。
出所：`docs/architecture/target/v2/kernel-mutation-prune-report.zh-Hant.md` 第 6 節（使用者 2026-11-19 承認、`v8-arch-gyo2-move-bs-mutants`）。

## 加える基準

1. **一つの改変に一つのミュータント**：find と replace が同じミュータントが清単にあれば、新しく立てない。
   別の Test case や別の Assertion も同じ改変を捕まえることを示すときは、既存のミュータントに合わせる（下の「合わせ方」）。
   `what` に書くだけでは足りない（`what` は実行されない）。
   前の Test case が実行を中断させる（`GYO_ASSERT` の abort など）ために後の case まで届かないときにだけ、別に立てる。
2. **Version と Format の定数**：定数ごとに一つ。版を上げるときは、そのミュータントの find と expect を書き換える。バッチごとに加えない。
3. **Design Invariants の条文と判定項目の下限**：独立に誤りうる決定（一つの条件、順序、既定値、エラーの種類、「しないこと」）ごとに少なくとも一つ。
   expect は、その決定を守る Assertion を指す。上限は置かない。
   ただし加えるときは「それが捕まえる誤りを、清単のどのミュータントも捕まえない」ことを書く。書けなければ加えない。
4. **守衛の Script**：
   - 規則ごとに三つ：規則全体を無効にするもの、実際のツリーでの陽性対照、fail closed。
   - 規則の中で独立に誤りうる分岐またはリストごとに一つ。
   - 走査の読み方（Comment、BOM、改行、属性など）のミュータントは、実際に見落としが起きた後にだけ加える（観測された Pressure、AGENTS §2）。
     加えたものは「読み方にすぎない」という理由で退けない。
   - リストの各項目は自己テストで一つずつ確かめる。リストのミュータントは一つでよい。
5. **実装の方式に縛る守衛**：守衛とそのミュータントは、AGENTS §3「ガードを立てる時期」に従い、scenario test が通るまで立てない。
6. **敵対的な検査の結果**：「壊しても検出されない箇所」が見つかったときは、まず分ける。
   捕まえる Test がないなら、Test とミュータントを加える。
   別の Test case も捕まえるべきなだけなら、1 に従い既存のミュータントに合わせる。
7. **機能を取り除く変更**では、同じ変更でそのミュータントを退ける。
8. **バッチごとの確認**：合併の前に、そのバッチで加えたミュータントを 1〜4 に照らして確かめ、数と理由を dev_log に書く。
   一つのバッチで加える数が「変えた Design Invariants の条文の数 × 5」を超えるときは、合併前の承認で理由を説明する。

## 合わせ方

既存のミュータント Y に、同じ改変を捕まえる別の case を合わせるとき：

- `cases`：Y の case に、加える case を足す（doctest の `-tc=` にそのまま渡る、コンマ区切りのリスト）。
- `expect`：どの文も失敗したときだけ一致するように書く。
  例：`(?=[\s\S]*(?:A))[\s\S]*(?:B)`。文はそれぞれ `(?:…)` で囲み、同じ文は一度だけ書く。
- `what`：合わせた元（ミュータントの id と、それが何を示していたか）を書く。
- 合わせた後に実行して、killed になることを確かめる。killed にならない（前の case が中断させた、など）ときは合わせず、元のミュータントを残す。

## 尋ねずに行い、事後に報告するもの

- 上の基準で立てないと判断したもの（同じ改変の別の case、定数のもう一つ、見落としの起きていない読み方、リストの項目ごとのミュータント）。
- 機能の削除に伴う退役。dev_log に一行書く。
- 守る性質を変えずに、改名や Message の変更に合わせる find と expect の書き換え（AGENTS §14.4 の「緩める面がない」場合）。

## 尋ねるもの

- 退けると、ある Assertion か自己テストが唯一のミュータントを失い、しかも既存のミュータントに合わせられない場合（AGENTS §14.4）。
- 守衛の規則そのものを立てる、分ける、延ばす場合（AGENTS §3）。
