# モデルの選択（ナビゲーターの規則）

ギアボックス（`agents/effort-gearbox.md`）は、同じモデルがどれだけ徹底するか（effort）を扱う。
この規則は、どのモデルが処理するかを扱う。
計画はペースノートであり、ナビゲーター（主会話の Claude。計画を読んでサブ Agent を起動する側）は、
計画を読んで、バッチと役割ごとにモデルを割り当てる。

## モデルの順序

2026-11 時点の順序：Fable ＞ Opus ＞ Sonnet ＞ Haiku。

- この規則の「大きい」「小さい」「上回る」「下回る」は、この順序で判断する。
- 「小さいモデル」は Sonnet 以下を指す。
- モデル名が変わったときは、この行と下の表を同じ変更で更新する。

## 役割

- 提案者：計画の案を出す。
- 統合者：提案者の案を比べ、一つの計画に統合する。
- 敵対的検査者：統合案（統合者がいない場合は提案者の案）を否定しようとする。
- 実装者：計画に沿って実装する。
- 審査者：code review を行う。
- 検証者：AGENTS.md §14.4 の 1〜5 の記述を実際のデータで確かめる。

`~/.claude/agents/xhigh-reviewer.md` のように定義にモデルがない Agent は、使う役割をその都度決め、
その役割のモデルを起動時に指定する（指定しないと主会話のモデルを継承する）。

## 上段と下段

上段は重い作業、下段はそれ以外を指す。次のいずれかに当たる作業を上段とする。

- Design Invariants、プロトコル、データ形式、公開インターフェース、Architecture の判断に触れる。
- 障害（インシデント）や回帰の修正。
- ユーザーが重要と指定した Feature。
- 上段と下段のどちらか判断できない。

## ultracode の workflow のモデル

ultracode の workflow（計画に限らず、証拠で示す作業や広範囲の走査を含む）は、
計画ができる前に動くことがあるため、規則で決める。

| 役割 | 上段 | 下段 |
|---|---|---|
| 提案者 | Opus | Opus |
| 統合者 | Fable | Opus |
| 敵対的検査者 | Opus（統合者が Fable のため） | Fable（統合者が Opus のため） |

- 敵対的検査者は、検査する相手（統合者。統合者がいない場合は提案者）と別のモデルを使う。
  目的は、盲点を重ねないことである
  （同じ重みの Agent は盲点を共有しうる。ultracode で Agent を増やしても、モデルの変更の代わりにならない）。
  検査者が相手より強いことは条件にしない。
- 表の組み合わせでは、Fable を使うのは統合者か敵対的検査者の 1 人だけになり、使用量の上限も抑えられる。
- 上段の計画に入力する偵察・走査には、小さいモデルを使わない（偵察の誤りは計画の誤りになり、後で見つけにくいため）。

## 計画が割り当てるモデル

- 計画は、各バッチについて、上段か下段かとその根拠（当たる条件）、
  実装者・審査者・検証者のモデルと理由を書く。
  ギアと並べて「モデル／ギア」の形で書き、ユーザーの確認を得てから実行する。
- 計画が割り当てるときの下限：
  - 上段のバッチでは、小さいモデルを使わない。
    ただし、上段のバッチの中の low の定型作業（ギアボックスの low の定義に当たるもの）は、計画に書けば小さいモデルを使ってよい。
  - 検証者は、4（緩めた性質が他の判定で引き続き守られているか）を確かめるときも小さいモデルを使わない。
  - 敵対的な検査では、少なくとも 1 人の敵対的検査者が、検査する相手と別で、小さいモデルより大きいモデルを使う。
    小さいモデルは追加の意見としてだけ使う。
- 上段では、主会話より大きいモデルを提案してよい（ユーザーの同意を得る）。
- 計画に割り当てのない §14.4 の検証者は、そのバッチの実装者の割り当てに従う。
- 計画に割り当てのないその他のサブ Agent は主会話のモデルを使う。
  定型作業（ギアボックスの low の作業）は小さいモデルでよい。
- 別のモデルを用意できないときは、同じモデルで行い、そのことを報告に書く。
- 実行中に割り当てを変えるときは、まず止めてユーザーに伝える（ギアボックスの切り替えの原則 5）。
- この規則より前に承認された計画は、バッチの開始時に、上段か下段かと実装者・審査者・検証者のモデルを補い、
  ユーザーの確認を得る。

## 失敗したとき

- 原因の判定はギアボックスの「失敗の判定」に従う。3 に当たるときだけ、モデルの変更を提案する。
- 変更先は、元のモデルと別で、元のモデルより小さくないモデルとする。
- モデルの変更は、AGENTS.md §14 冒頭の報告の後にユーザーが決める。

## モデルを決める人

- 主会話のモデル：ユーザーだけが決める。
- workflow 内の各サブ Agent、および Claude が別に開く session のモデル：
  計画の割り当て（ultracode の workflow ではこの規則の表）に従って Claude が設定し、
  起動前にモデル、ギア、種類、渡す資料を主会話に示す。
- 主会話を上回る場合、または承認済み計画の割り当てやこの規則の表を下回る場合は、ユーザーの同意を得る。
- 指定しない項目は「継承」と書く。実際の値はユーザーが /tasks で確認できる（環境変数が上書きしうる）。
