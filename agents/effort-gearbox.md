# 作業の分割とギア（ギアボックスの規則）

複数の手順からなる作業では、まず作業をバッチに分け、バッチごとにギア（思考の深さ、effort）を選ぶ。

## ギア

- low（1 速）：状態の確認、コマンドの実行、ファイルの移動、指示どおりの逐語的な修正。
- medium（3 速）：文書、整理、範囲が明確な小さな修正、受け入れ検証の実行と結果の記録。
- high（4 速、主力）：既存の設計を理解してからの実装、複数ファイルにまたがる修正、code review。
- xhigh（5 速）：局所的にだけ使う。タイミング、プロトコル、決定性など、気づかないうちに誤りやすいロジック。
- max（追い越し）：まれに使う。何度も失敗している問題、または厳密な論証が必要な問題。
- ultracode（四輪駆動）：一段高いギアではなく、別の駆動方式（複数の Agent の協働）。
  用途：バッチの計画、証拠で示す必要があること、高リスクの変更（プロトコル、データ形式、公開インターフェース）、広範囲の走査。
  規模は小さく保つ：案は約 3 つ、審査者 1 人、対抗的な検査 1 回。

## ギアの切り替えの原則

1. 要求が大きい、または曖昧なときは、まず ultracode か xhigh で計画し、検収点のあるバッチに分ける。
   各バッチに推奨のギアを書き、計画がユーザーに確認されてから実行する。
2. 通常の実装は high、文書と実行は medium。
3. リスクのある部分だけ xhigh に上げ、終わったら下げる。
4. 後で外部の検証（CI、Test、ユーザーの確認）がある作業は、低めのギアでよい。
   外部の検証がない作業は、ギアを低くしすぎない。
5. 実行中に状況が変わった場合（回帰の発見、範囲の拡大など）は、まず止めてユーザーに伝え、計画し直す。
   黙ってギアを上げ下げしない。

## ギアを決める人

- 主会話のギアと ultracode の切り替え：ユーザーだけが決める。
- workflow 内の各サブ Agent のギア、および Claude が別に開く session のギア：
  Claude が設定し、開始前に説明する。主会話のギアより高くする場合は、ユーザーの同意を得る。
- ultracode の使用を勧めるときは、先にユーザーに尋ねる。
