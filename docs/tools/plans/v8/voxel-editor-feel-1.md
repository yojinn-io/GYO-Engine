## 範圍（照你最痛的順序）

### F1 縮放（H5，最痛的第 1 個）

- **上下限**：
  - 下限：注視點前 2 格（1 m）。
  - 上限：依地圖大小，取框住整張地圖的距離，和 0 鍵的取景相同（地圖格子範圍對角線的 0.9 倍，至少 4 格）。地圖改變範圍時跟著變，不寫死。
- **拉遠時繪製距離跟著擴大**：
  - 實際的繪製距離取下面兩者較大的那個：
    - 面板上的繪製距離（ve-cull 的滑桿）；
    - 「目前相機距離能看到的範圍」：相機距離的 1.5 倍。
  - **上限（到 ② 之前）**：畫的區塊數不超過 2,000（ve-cull 的 CB2 預算）。超過時，從離注視點近的區塊起取 2,000 個，畫面上提示「已達上限，遠處未畫」。
  - building 規模（768 區塊）一定全畫；km² 地圖的全局要等 ②。
- **滑桿與鎖定**：
  - 面板加「縮放」滑桿，可以拖動，範圍是上面的上下限；以對數刻度顯示，近處細、遠處粗。
  - 加「鎖定」勾選：勾上後，滾輪不改距離，滑桿仍可拖。
  - 0 鍵（框住整張地圖）照舊。

### F2 左邊面板分組（最痛的第 2 個；含 H3 的「找不到改朝向的地方」）

- **分成四組**，每組是一個可以收合的標題：
  1. **檔案**：路徑、存檔、undo／redo。
  2. **工具與模式**：工具、模式、筆刷大小與形狀、snap、編輯平面。
  3. **方塊與朝向**：選方塊、朝向（Q／E、Shift），朝向緊鄰方塊。
  4. **檢視與相機**：縮放滑桿與鎖定、繪製距離、畫了幾個區塊、視角鍵說明。
- 只搬位置、改標題，**不改任何功能與快捷鍵**。

### F3 朝向看得見（H3）

- **懸停的線框上畫朝向箭頭**：
  - 方塊的「上」方向一支箭頭，「正面」一支箭頭，兩支不同顏色。
  - 只在放置的工具（Brush、Shape、Line）、Add 與 Paint 模式下顯示。
- 用 ImGui 的線畫，和線框、格線同一層，不是區塊幾何（DI 7 不受影響）。
- ghost 預覽（顯示方塊本身）不做；之後若箭頭不夠，再另外宣告。

### F4 相機朝向的軸箭頭（H8）

- **位置**：預覽的左下角，畫 X（紅）、Y（綠）、Z（藍）三支箭頭，隨相機旋轉，照 Goxel 的做法（只參考行為）。
- 用 ImGui 的線與字畫，不經區塊幾何。

### F5 Line 改拖曳（Q10）

- **新的操作**：按下設起點，拖曳中跟著游標顯示整條線（同 Shape：放回上一條、畫新的一條），放開才成為一步 undo；Esc 取消。
- 拖曳中拾取看拖曳開始時的地圖（和其他工具相同）。
- 拿掉「點兩下」的做法與它的提示文字。
- Brush 的 Shift＋點擊（從上一筆畫線）照舊。

## 不做（本批）

- **自由相機、多層建築的穿牆**：最痛的第 3 個。另批 `ve-free-camera`，在本批之後宣告。
  - 理由：要改相機的操作體系，可能牽涉 framework 的相機。
  - 穿牆的顯示（相機附近不畫／剖面）在那一批比較。
- **②**（只上傳繪製距離內的區塊等）：另批。km² 的全局要等它。
- **其他**：
  - ghost 預覽；
  - 往游標縮放、左鍵空白旋轉（調查裡你沒有選）；
  - 正交投影；
  - 拖曳開始的整份複製（km² 按下約 100 ms，你在 building 上沒感覺到延遲，H1 選不是問題）。

## 契約影響

- DI 1～7 都不變。
  - 只改視窗（`src/window/`）與核心裡新增的純函式（縮放範圍、繪製距離的取法）。
  - 不新增依賴。
  - 疊加的圖形（箭頭）都用 ImGui，不產生區塊三角形。
- 不改格式、不改 Engine、不改 framework。

## 判定

| 代號 | 判定 | 根據 |
|---|---|---|
| E1 | 縮放範圍的純函式：給地圖範圍與格子大小，算出上下限；空地圖、單格地圖、km² 地圖各一案；距離被夾在上下限之間 | CPU 規則測試＋突變 |
| E2 | 實際繪製距離的純函式：面板值與相機距離取大；區塊數超過 2,000 時取最近的 2,000 個、回報已達上限；building 規模一定全取 | CPU 規則測試＋突變 |
| E3 | Line 的格子集合：拖曳的起點與終點給出的集合，等於現在點兩下給出的集合（同一個 `StrokeCells`）；拖曳中換終點不留下舊的線（放回再畫） | CPU 測試（`EditSession` 層面）＋突變 |
| E4 | 預算：building 拉到最遠，影格 p95 ≤ 16.7 ms；km2-ground 拉到最遠，畫的區塊數 ≤ 2,000、影格 p95 ≤ 16.7 ms（量法同 ve-cull，600 幀丟前 60，Chrome 關閉，舊版對照） | 量測（先宣告，看結果後不放寬） |
| E5 | 本機 `cpu|shader` 全部通過；L1 三平台通過 | CI |
| L3 | 你在視窗裡試：縮放的上下限、滑桿與鎖定；四組面板；朝向箭頭；軸箭頭；Line 拖曳。合格與否由你判斷 | 試用 |

- 面板分組、箭頭、軸箭頭是畫面上的事，沒有 CPU 測試，靠 L3。
- 鍵表沒有重複的測試（設計稿 §3.5）：本批不加新鍵，所以不做。

## 對機器的影響

- E4 的 building 與 km2-ground 拉到最遠：畫的區塊數受 2,000 的上限，預期每幀約 8 ms（CB2 的量級）。
- 跑之前照慣例先問你。
