# v8 工具：拾取在編輯平面那一層的平手修正（`ve-pick-tie`）事前宣告

更新：2026-11-07。Owner：voxel 地圖編輯器線（本會話）。紀錄：[HANDOFF](voxel-map-editor-HANDOFF.md)。

**狀態：2026-11-07 你選「今、小さな修正バッチで」。PT1～PT3 成立（[dev_log](../../../dev_logs/2026_11_07_tool_v8_voxel_pick_tie.zh-Hant.md)）。**

## 缺陷

- **現象**：km2-ground 的近距離延遲量測（`ve-feel-survey`）裡，固定的兩個畫面位置按下 Add 什麼都沒放。
- **原因**（已用量測的射線值確認）：
  - 射線從上方進入編輯平面那一層（y = 0）的已填格時，有兩個 t 值。
    - DDA 用累加算出的進入點 t：337.2832555517757。
    - 直接算出的平面 t：337.2832555517746。
  - DDA 那個大約 1e-12，迴圈的 `entered > planeT` 就提前結束。`Pick` 回傳「平面上的格」，但那一格已經填了。
- **違反的約定**：`Pick` 的說明（`Editing.hpp`）寫「a filled cell the ray enters where it meets the plane (one in the plane's layer) wins」。現有測試只用軸向的射線（t 精確相等），所以沒抓到。
- **影響**：視窗用同一個 `Pick`、同一個預設編輯平面（y = 0），點地面時會在部分位置放不下（H2 的實例）。

## 修正（§14.3）

1. **Red**：在核心測試加一條規則測試。用量到的射線（km2-ground 的值），編輯平面 y = 0，那一格已填。斷言回傳的是那一格本身（不是 onPlane），法線朝上。先確認失敗。
2. **修正**：DDA 走進「編輯平面那一層」的格時，不拿進入點的 t 和平面的 t 比大小。那一格就是平面所在的層，有填就回傳它；沒填才看平面。
   - 平面在已填格之前的情況（二樓蓋在一樓上方）不受影響：那時 DDA 在進入平面那層之前，就已經超過平面的 t。
3. **Green**：同一條測試不改，確認通過；既有的 W3 拾取測試全部照舊通過。
4. **突變**：加一個「拿掉那一層的例外」的突變，期待新測試以 `is NOT correct` 失敗。

## 不改

- `Pick` 的介面、拾取距離、snap 的規則、DI。
- 量測方法：修正後，用同一個宣告（`--orbit-distance 330`，40 輪確認，再 300 輪）重跑 km2-ground。
