## 5. 和宣告、閘口不同的地方（已在各 dev_log 揭露，這次要你看）

| 不同 | 內容 | 為什麼 |
|---|---|---|
| **看不到的實體用 `Exited`，不用 `NotSent`**（宣告 D-7） | 宣告寫「看不到＝這份沒帶」。實作：看不到就在 Client 刪掉（WhileVisible），K3 寫 `Exited`；`NotSent` 改用在「看得到、但值因預算延後」 | 宣告選了 WhileVisible，看不到的實體不該存在於 Client；用 `NotSent` 會讓它留著。宣告原文沒改，加註「第 5 步偏離，未經核准」 |
| **值訊息多一段延後清單**（wire） | 第 0 則在 Resource 之後多 `u16` 個數＋實體編號；`kNetProtocolVersion` 升到 3 | K3 要知道哪些實體這個 tick 沒帶，才守得住 R-8 B 的前提 |
| **NT-E6** | K3 上可回滾、V≠R、沒有轉換的 Resource，`Check` 回錯誤 | 你定的 U2 (a) |
| **入口忘掉退出已生效的實體**（S6） | `Prune(C, C 的存活集合)` 丟掉退出已生效、存活集合也沒有它的實體 | 入口原本從不丟，記憶體與成本一直長；也是 B1 的修法之一 |
| **閘口後新增的兩句**（M5） | R-8 A 裡兩句（明說的存活和記下的不同本身就是回滾的理由；還原時把 C 的存活集合換成明說之後的） | 實作需要；標「閘口後新增、未經閘口」 |
| K3 的生成晚約一個來回 | 網路生成的實體不在 `First` 生成，等確認點的回滾放回 | 在 `First` 先生成會在回滾到 C 時被閘口 1 的 A 刪掉，不回滾的元件也跟著沒了 |
| 回滾深度用 `DefaultInputLength()`（M4） | 網路判斷「晚到超過深度」用官方策略的這個值；作者自己的策略回 0 時不丟 | 回滾沒有查深度的 API，這次不擴大；寫成限界 |
| 優先度 | 取 lightyear 累積優先度的概念（出處更正為 `send_reliable.rs`），做法不同；不取 replicon 的 `priority × tick 差`（它限的是頻率） | — |
| 可見性的形狀 | 作者填 Peer 上的集合（replicon `ClientVisibility`），不做篩選元件 | 單一用途不另立抽象 |
| 預算的位置 | `NetEntry::ValueBytesPerTick`，只算值的實體部分 | — |
