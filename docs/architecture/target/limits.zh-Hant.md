## 說明

- **Serial 的範圍**：LIM-2 只限制一個 World 內 System 的並行。Match 的 IO 執行緒、模擬執行緒、Client 的主執行緒與音訊回呼，各是不同 World 的 runner 或外部服務，彼此並行，與今天相同。
- **為什麼 C++ 要守衛而 Bevy 不用**：Bevy 能預設並行，是因為 Rust 的借用檢查保證存取宣告可信；C++ 做不到（LIM-3），所以並行時要另外證明判定的結果和 Serial 一致（Kernel 原本的 X-2 守衛隨第 4 批拿掉，LIM-2）。（使用者 2026-11-22 核准，`v8-arch-gyo2-authority-rollback`）Bevy 預設忽略歧義是目標不同（它不以跨平台位元一致為目標），不是語言差異。
- 本頁與各部件文件的 Replacement Criteria 的分工：部件內的置換條件留部件文件；跨部件、或會出現在批次事前宣告「範囲の限界」裡的，列本頁。
