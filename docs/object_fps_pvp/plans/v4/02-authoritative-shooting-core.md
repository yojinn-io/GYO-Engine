# 第 02 批：權威射擊核心

依賴：第 01 批完成。先讀 [交接](HANDOFF.md) 及 [v4 契約](../../protocol-v4.zh-Hant.md)。
本批已依使用者指示完成，2026-09-28。沒有開始第 03 批，沒有執行長測。
交付、短測及限制見 [dev_log](../../../dev_logs/2026_09_28_pvp_v4_batch02.zh-Hant.md)；
接續使用 [交接](HANDOFF.md)。以下保留本批原定範圍與完成條件。

## 目標與邊界

在不依賴網路、SDL 或 Renderer 的產品 domain 完成射擊裁決。線上仍使用 v3 移動；
新增能力以產品單測直接驅動，不加入正式遊戲的測試控制或空白 v4 wire。

## 實作

- 增加普通 C++ 射擊請求、裁決、戰鬥狀態、CombatRules 與有界動作帳本，依契約
  實作 ActionId、32 個 ID 窗口、連續確認下界及原子批次驗證。
- 請求含 ID、參考 Authority Tick、絕對 yaw／pitch；裁決含 ID、裁決 Tick、
  接受／拒絕及原因、命中種類、目標與實際傷害。血量／冷卻與移動預測狀態分開。
- 每 Tick 先完成所有玩家移動，再處理動作；按接受 Tick、玩家 ID、ActionId 排序。
  世界不等待缺號，不補開積欠射擊。使用原裁決處理重送，不刷新期限或冷卻。
- 共用 Engine 的射線／膠囊／AABB 查詢；角色為 Arena 身體膠囊，牆／地板阻擋，
  同距離遮蔽物優先，排除射手自己；不載入 Campaign 或 Renderer。
- 冷卻、期限與非法參考得到明確拒絕；未命中是接受的射擊。HP 歸零仍可操作；
  Join 恢復滿血，Leave 清場；movementEpoch 不清除射擊狀態。
- Match domain 不讀時鐘。Host 保存有界發布時間索引，傳入可信年齡上下文；
  確定性測試可直接提供時間，不新增 Engine 時鐘或 Client wall-clock 欄位。
- 接受動作前預留裁決容量；滿載／超窗無效果且可保留原 ID 重試，確認後只回收
  對應資料，退休下界仍防止舊操作復活。

## 短測與完成條件

- 命中／未命中、遮牆、射程、上下瞄準、排除自己；固定傷害與 HP 下限。
- 冷卻前／邊界／後、期限邊界、未知／未來參考 Tick。
- 重複只生效一次，衝突批次不部分生效，重送已裁決動作不改原答案。
- 窗口滿、缺號、亂序、確認遺失、退休 ID、movementEpoch 重設及離開重入。
- 無射擊時既有移動測試不變；Match 仍不依賴 SDL／Renderer。
- 交付 domain、短測與 dev_log；更新進度／交接後停止，不自動開始 v4 傳輸。
