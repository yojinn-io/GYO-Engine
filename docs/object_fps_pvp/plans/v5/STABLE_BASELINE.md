# PvP v5 穩定基線

升格日期：2026-10-03。Owner：`object_fps_pvp`。
依使用者決定（2026-10-02「v5結案＝第05批＋完整驗收＋全部通過即升格」）完成第05批完整驗收後，**v5升格為穩定基線**。
範圍為 **macOS 26.7.1、Intel x86_64、SDL視訊驅動cocoa、Metal、60 Hz顯示器、同機三角色**，以及既有受控網路／阻塞／跨生命恢復測例。
這是已驗證範圍的開發基線，不代表Windows、Linux、實體LAN、兩台機器的時鐘漂移、GUI長時間運行或射擊回溯已驗證。
v4的[穩定基線](../v4/STABLE_BASELINE.md)原樣保留。

## 固定契約與版本

Client／Gateway／Match共同使用v5，詳細政策以[v5契約](../../protocol-v5.zh-Hant.md)為準。重點：

- 60 Hz Authority與本機固定模擬、Snapshot 60 Hz；兩步移動lead、1 Tick遠端插值；輸入worker以60/s token bucket送出，持續相位追蹤。
- 3D跳躍與預測；12發彈匣、R換彈90 Tick（1.5秒）、10 Tick冷卻、100 HP、每發25；死亡等待180 Tick（3秒）後重生，生命世代隔離動作與效果。
- 連線品質移出：10秒窗口內被代替的命令超過5%即警告，連續3個窗口不合格即移出。
- Client呈現：女性人物、Walk／Jog依速度混合、上半身射擊／換彈、跳躍三段、Death01；第一人稱射擊與換彈。

## 驗收過程中保留的跑次

失敗與中斷全部保留，不覆寫；每次處理都寫在證據目錄的`declaration.md`補充宣告。

1. 60 Hz長測原判定失敗：3次重生首幀時間重設的幀長（21.8～23.1 ms）超過舊規則上限`1/fps＋5 ms`。原因是macOS的`sleep_until`在60 Hz常晚醒3～8 ms，
   規則假設了主機計時精度。使用者選規則B（結構條件，不依賴計時精度），以同一份原始資料重新分析為通過；只有那3筆改變。
2. 144 Hz第一次（`soak144-interrupted/`）：約1800秒時被執行工具的30分鐘背景上限中止，無效。
3. 144 Hz第二次（`soak144-disturbed/`）：Match一幀99.4 ms捨棄1 Tick，同時刻Client probe也變慢，判為整機瞬間停頓；依乾淨長測定義屬受干擾。使用者選擇重跑。
4. 144 Hz第三次（`soak144/`）：通過。

## 限制與後續

- 未執行：Windows、Linux、實體LAN、兩台機器的Client／Host時鐘漂移、GUI長時間運行。
- 同機三角色共用一個時鐘，測不到時鐘頻率差；長測是headless，不是GUI長測。
- 已知產品限制（延到v6）：遠端上半身俯仰瞄準、受擊反應、macOS拖動或縮放視窗時Engine呈現阻塞約1秒（可能短暫出現`CONNECTION POOR`）、
  本機射擊冷卻閘約2 Tick落差、死亡時持槍手臂（待釐清）。
- 驗收工具：計時器基線紀錄、跨平台相容性稽核列出的計時／視窗假設、v4驗收工具清理。
  見[v6交接](../v6/HANDOFF.md)。
