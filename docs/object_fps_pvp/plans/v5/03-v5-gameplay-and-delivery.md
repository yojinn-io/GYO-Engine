## 玩法與責任

| 項目 | 已批准的 v5 規則 |
|---|---|
| 手槍 | 左鍵上升沿單發；100 HP／25 傷害；接受後冷卻 10 Authority Tick |
| 彈藥 | 12 發彈匣、無限備彈；有效射擊由權威扣彈，拒絕不扣彈 |
| 換彈 | R 發起；90 Authority Tick 後由權威補滿；合法性及同 Tick 次序依契約 |
| 跳躍 | Space 上升沿、接地時起跳；高度 0.6 m、重力 18 m/s² |
| 死亡／重生 | HP 歸零進入死亡狀態；180 Authority Tick 後自動重生，出生阻塞依契約處理 |
| 排除 | 不新增近戰、收槍、武器切換、命中回溯、骨架部位傷害或通用動作框架 |

Match 擁有 HP、彈匣、換彈、死亡、重生與 lifeGeneration；Client 只能送操作意圖，不能
宣告傷害、補彈、存活、重生位置或可信動作時間。規則由 Match 經 Ready／Welcome
下發，Client 不手工維護另一套權威預設。無限備彈是明確政策，不用持續補寫巨大
有限整數或使計數溢位來模擬。

`object_fps_v2` 的 PlayerController／WeaponController 是行為參考。PvP 活躍的
`StepMovement`／`PvpMatch` 承接玩法，保留產品既有固定步進與帳本；不得整批啟用
Campaign／GameSession，亦不新增對 v2 owner、Editor、SDL 或 FBX 的 Match 依賴。
既有 CSV 並非目前 PvP combat 的數值來源；不能同時保留兩套有效的手槍設定。

## 跳躍、預測與生命週期

- 在產品既有 command／state 中加入契約要求的跳躍與垂直狀態，使權威、預測、
  replay 使用同一個 `StepMovement`。相機、受擊膠囊、射線起點與遠端模型都以
  權威／預測腳點高度為基礎，不能只讓相機上下移動。
- 保留 v2 的起跳條件、常加速度積分、完整膠囊掃掠與落地／撞頂處理；PvP 水平
  速度仍不受 pitch 影響。長按、半空重按、重送或 Held fallback 不得重複施加起跳。
- 一個呈現幀沒有產生 fixed command 時，按下沿不能丟失；一幀產生多個 command
  時也不能重複。失焦、Tab、滑鼠重新捕捉、死亡與重生的輸入釋放依契約處理。
- 死亡期間不接受受控水平移動／跳躍／射擊／換彈效果；正常 Running 步繼續生成
  中立命令並執行垂直物理，使空中屍體落地。到期重生由權威執行。暫停 Client Drain
  或渲染不能暫停 Match 的換彈／重生計時，也不能一次補開多次效果。
- lifeGeneration 識別玩家的這一條生命；movementEpoch 識別移動命令序列的有效期，不能
  用其中一個暗示另一個。重生建立新生命與新的移動起點，清除該玩家舊生命的
  預測／插值殘留，不清除其他玩家時間線；一般移動恢復不重設生命、HP、彈匣或帳本。
- 出生點選擇、阻塞時的等待／重試及兩玩家同時死亡依契約保持確定次序，不把角色
  傳入障礙物或另一個活玩家。死亡目標的命中資格與碰撞資格必須跟隨生命狀態。

## 一起升級 wire 與合法恢復

- 兩份產品 Protobuf、C++／Go bindings、codec／adapter、建置引用、HTTP join、
  Ready／Welcome、ClientConnection、Host／Gateway 及產品 probe 一起使用 v5。
  三角色明確拒絕舊版，不保留混合 v4／v5 分支或靜默忽略新增欄位。
- 動作類別、生命參照、權威戰鬥狀態、拒絕原因與規則完整映射；C++ 與 Go 同時
  驗證非法 enum、缺漏、最大值、重複 ID 內容衝突及有界批次，不能只檢查 happy path。
- 每個 ActionRequest 各帶 `lifeGeneration`，不能只在 ActionBatch 放一個共用
  世代；同一個重送窗口可同時有跨生命未 ACK 動作。Input 窗口可帶單一
  `lifeGeneration`。結果帶動作 kind、請求生命世代與命中目標生命世代，供 Client
  與驗收器按生命對帳，不根據裁決到達時間猜測傷害屬於哪條生命。
- 同 Session 的 ActionId 在死亡／重生後持續遞增。既有不可變裁決與尚未確認的
  帳本跨 lifeGeneration 保留，不能因重生把 ActionId 歸零、清帳本或換 ID 補送同一操作。
- 已裁決的舊生命動作重送時仍得到原裁決；尚未裁決、已失去生命資格的動作取得
  明確 terminal 拒絕並正常交付、確認、退休。不能只在某層丟棄，讓 Client 無限重送。
- 動作去重以 Session／ActionId 為邊界；life 參照是不可變內容的一部分。相同 ID
  改生命或動作內容仍屬衝突，不可藉此再次執行。過期、死亡、錯誤生命、空彈匣、
  換彈中等拒絕皆無傷害、無扣彈或補彈副作用，具體分類依契約。
- HP／ammo 依 PlayerId／lifeGeneration 與權威 Tick 解讀，不做移動插值或被 replay 覆蓋。
  延遲送達的舊生命裁決可完成帳本退休，但不能覆蓋新生命 HUD、重播動畫或再次扣血。
- Leave、Session 到期與斷線仍清理各自資料；重生、movementEpoch 恢復、主執行緒
  停頓不等同換 Session。保留連續 ACK 不跨洞、結果非破壞性保留與有界交接規則。

- 原有 Mark23 與人物 idle／jog 保持可用。權威功能不能等待第 04 批動畫才可驗證；

## 短測與基準替換

1. **Domain／預測：**10 Tick 邊界、12 發耗盡、空彈拒絕、90 Tick 換彈及中途死亡、
   180 Tick 重生、同 Tick 相互命中／死亡與裁決順序；跳躍頂點、落地、撞頂、
   半空重按、固定步進 replay、重生清理及出生點阻塞。生命開始、結束與效果各一次。
2. **刻意更新 v4 測例：**原本「HP=0 仍可移動／射擊／被命中」是已批准的 v4
   政策，不是當成 bug 隨便刪除。v5 用死亡抑制與自動重生的新斷言替換，保留
   v4 歷史證據；100 HP 飽和後只觀察零傷害的分析方式改為逐生命核算。
3. **帳本：**跨生命未確認裁決、死亡前排入但死亡後裁決、舊生命封包延遲至重生、
   ACK 缺洞、同 ID 改 life／種類、重複換彈、重生中斷線／重入；每 ID 至多一次效果，
   舊生命未決動作最終拒絕且窗口可退休，移動恢復仍保留 HP／ammo／life／帳本。
4. **Wire／服務：**codec／adapter、版本拒絕、最大合法封包、Go race、C++ 與
   Client／Match／Gateway／probe 建置；完整 UDP 含 header 仍 ≤1,200 bytes，
   動作窗口 ≤32、批次 ≤8，不提高 Session 120 包／秒或額外動作 30 Hz 上限。
5. **真 socket 共存與恢復：**30／60／144 Hz Client 下移動＋跳躍＋合法射擊／
   換彈／死亡重生；RTT 0／20／40 ms、最多 10 ms 單向抖動、5% 丟包、連續兩包
   遺失，首請求／裁決／ACK 遺失、重複／亂序／衝突，以及上／下行、Gateway、
   Host IPC 等既有 250 ms／1 秒阻塞。覆蓋跨 reload／death／respawn 的干擾，
   並重驗主執行緒停頓、movementEpoch 恢復、Leave／重入與斷線清理。

恢復既有門檻不變：生還、可操作且 Session 有效的故障測例，在干擾解除後 1.5 秒內
恢復新操作裁決與移動，移動需維持至少 250 ms 穩定觀察。死亡的 3 秒玩法等待
另列生命驗收，不延長其他網路恢復門檻。過期或舊生命動作以合法 terminal 拒絕收斂，
不能用事後補射達成接受率。乾淨跑次的合法動作與故意非法的壓力測例分開統計。
v4 的移動延遲、Actual、跨視窗配對等門檻完整保留，見契約與第 05 批計畫。

GUI 只作本批必要的有限操作／HUD 短回歸；不得執行完整 GUI 三輪或長測。
所有跑次預先列事件分母、生命範圍與預期裁決，不能事後剔除死亡／換彈時事件
來提高通過率。因重生造成的 epoch 變更與 backlog／恢復重設分別記錄。

2026-10-01／02經使用者批准的補充需求：低於約54.5 FPS（平均幀間隔>1.1 tick）不做啟動相位對齊，
見 [fix/01](fix/01-a1-low-fps-regression.md)；計次 GUI 延遲輪的視窗干擾判定與補跑規則
（只依視窗證據、每輪至多補跑一次、事前宣告）見 [fix/06](fix/06-gui-window-interference-and-rerun-rule.md)。
