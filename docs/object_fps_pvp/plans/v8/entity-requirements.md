# 實體需求問卷：迷你塔科夫的實體種類、數量與歸屬

更新：2026-11-01（`v8-product-tarkov-requirements`）。Owner：`object_fps_pvp`。**狀態：草稿，等你填答。** 起因：架構例行掃描開出的「PvP Match 的實體資料模型」卡（`v8-product-entity-model`，[HANDOFF](HANDOFF.md)）；使用者 2026-11-01 決定迷你塔科夫是 `object_fps_pvp` 的演進（README「未決事項」a），要在第一個非玩家實體進來前把資料模型定好。

## 怎麼填

- 依 AGENTS §2「Feature → Contract → Architecture」：實體契約（`v8-product-entity-contract`）要先知道「有哪幾種實體、同時幾個、一局生出幾個、誰看得到、誰持有」，才能決定 id 的位寬、元件的清單與複寫的通道。這份問卷只問玩法，不問做法。
- 每一題都有「典型值」，是照 [pv8 需求問卷](pv8-requirements.md)的典型值與 [protocol-v8 附錄 C](../../protocol-v8.zh-Hant.md) 推的假設。你可以直接改數字、寫「典型值」，或寫「不做」。
- 數字只要量級對。會改變做法的門檻寫在各節的「這題決定什麼」。
- pv8 問卷已問過的題目不重問，直接沿用其典型值並標出題號；要改請在那份問卷改。
- 填完之後的下一步：`v8-product-entity-contract`（ultracode，另外徵求同意）。

## 1. 實體種類與數量

這題決定什麼：**id 的位寬**（同時存在的上限決定陣列大小；一局與一個程序生命期內生出的總數決定 id 什麼時候用盡）、**哪些種類要進高頻 snapshot**。

| # | 問題 | 典型值 | 你的答案 |
|---|---|---|---|
| 1-1 | 除了玩家、AI 小怪、Boss、投射物、地上物品、容器、屍體、放置物，還有哪些會「存在於世界、有位置、會出現或消失」的東西（門、可破壞物、撤離點、觸發區、載具……） | 門 ≤ 50（開關狀態）、撤離點 ≤ 6（固定，不是實體）；沒有載具與可破壞物 | |
| 1-2 | 一局**同時存在**的實體總數上限（所有種類相加） | 約 400：玩家 8＋AI 20＋Boss 1＋投射物 16＋物品 200＋容器 40＋屍體 ≤ 28＋放置物 8＋門 50 | |
| 1-3 | 一局**累計生出**的實體數（投射物與掉落物會不斷生與滅） | 約 20,000：投射物佔大多數（每人每分鐘 30 發 × 8 人 × 60 分） | |
| 1-4 | 一個 Match 程序生命期內累計生出的實體數（決定 id 何時用盡；對照 1-2 的 65,535 位玩家） | 7 天不重啟、每局 60 分 → 約 3,400,000 | |
| 1-5 | 投射物是不是真的要當實體（有位置、要同步給別人看），還是只要「生成事件＋共用的純軌跡規則」讓 Client 自己算（附錄 C 的做法） | 生成事件＋純軌跡；不當每 Tick 同步的實體，但要有 id 讓命中結果能指它 | |
| 1-6 | 一局最多幾隻 Boss、幾種小怪（種類數影響「種類是標籤還是型別」） | Boss 1 隻 1 種；小怪 3 種 | |

## 2. 身分

這題決定什麼：**玩家與非玩家是否共用一個 id 空間**、`hit_entity_id` 能不能一個欄位指到任何東西、Client 要不要知道「這是誰」。

| # | 問題 | 典型值 | 你的答案 |
|---|---|---|---|
| 2-1 | 同一位玩家在一局內會不會「死了再回來」（重生、換角色）；回來之後別人要看成同一個人嗎 | 死鬥模式重生、撤離模式不重生；都看成同一個人（生命世代用 `life_generation`） | |
| 2-2 | 玩家的屍體是不是和玩家分開的東西（可以被搜刮、會留在地上） | 是，分開的；撤離模式的屍體留到局末 | |
| 2-3 | 命中結果要不要指出「打到的是什麼」的種類（玩家／AI／Boss／門），還是只要 id、種類由 Client 自己查 | 只要 id；Client 從 snapshot 已知的實體查種類 | |
| 2-4 | 有沒有「一個實體掛在另一個實體上」的情況（撿起的物品在背包裡、放置物黏在牆上、技能跟著人走） | 有：物品進背包後離開世界、改成背包內容；放置物固定；技能效果跟著人 | |
| 2-5 | AI 要不要像玩家一樣有「連線品質」「輸入視窗」這類東西，還是 AI 的輸入每 Tick 都在 | AI 的輸入每 Tick 都在，沒有連線相關的狀態 | |

## 3. 人物屬性

這題決定什麼：**身體（Body）與戰鬥（Combat）元件要不要拆更細**、哪些屬性是「每個實體都有」、哪些只有玩家有。

| # | 問題 | 典型值 | 你的答案 |
|---|---|---|---|
| 3-1 | 人物有哪些會變的屬性（血量、護甲、體力、負重、飢餓、出血……） | 血量、護甲值（來自裝備）、負重（決定移速）；沒有體力、飢餓、出血 | |
| 3-2 | 哪些屬性 AI 與 Boss 也有 | 血量、護甲值；AI 沒有負重 | |
| 3-3 | 哪些屬性別人看得到 | 都看不到數值；只看得到死活、姿勢、裝備外觀；Boss 血量所有人看得到（pv8 6-2） | |
| 3-4 | 屬性有沒有「同一局內永久改變」的來源（升級、強化、拾取增益） | 只有裝備帶來的護甲與負重，換裝備就變 | |

## 4. PvE 規模與 AI 行為

這題決定什麼：**Match 每 Tick 要推進多少實體的移動與戰鬥**、AI 的「輸入來源」長什麼樣、AI 要不要回溯判定。

| # | 問題 | 典型值 | 你的答案 |
|---|---|---|---|
| 4-1 | AI 的移動和玩家一樣嗎（同一套走、跑、蹲、跳、碰撞），還是有自己的規則（飛、穿牆、瞬移） | 一樣，走同一套 `StepMovement`；Boss 多一個不受碰撞推擠的規則 | |
| 4-2 | AI 用什麼打人：和玩家一樣的槍（走同一套射擊判定），還是各有攻擊方式（近戰、投射物、範圍） | 小怪用槍，同一套判定；Boss 多近戰與投射物 | |
| 4-3 | AI 會不會打 AI；AI 之間有沒有陣營 | 不會；AI 全部一個陣營，只打玩家 | |
| 4-4 | 玩家打 AI 時要不要像打玩家一樣回溯到射手看到的時刻（rewind-line） | 要，同一套；AI 也走 Match 的動畫狀態與 hitbox | |
| 4-5 | AI 的決策多常做一次（每 Tick、每 N Tick、事件驅動） | 每 6 Tick 想一次（10 Hz），移動每 Tick 照上次決定走 | |
| 4-6 | AI 的決策要不要「可重現」（兩台 Match 給同樣輸入得到同樣結果），還是只要 Match 自己一致 | 只要 Match 自己一致；但亂數要有種子、能在 digest 裡重現 | |

## 5. PvP 與 PvE 的組合

這題決定什麼：**一個 Match 內會不會同時有「連線的實體」與「非連線的實體」互相攻擊**、陣營是不是元件、同一套規則要不要切模式。

| # | 問題 | 典型值 | 你的答案 |
|---|---|---|---|
| 5-1 | 玩法模式有哪些；同一局會不會混合（例如撤離模式裡玩家互打、也打 AI） | 死鬥（純 PvP）、撤離（PvPvE 混合） | |
| 5-2 | 有沒有隊伍；隊友能不能互相傷害 | 撤離模式最多 2 隊（pv8 9-4），無友軍傷害；死鬥各自為戰 | |
| 5-3 | 玩家中途加入或離開時，他的 AI、物品、屍體怎麼處理 | 屍體與掉落物留在世界；AI 不屬於任何玩家 | |
| 5-4 | 一局結束時哪些東西要留到結算（擊殺數、帶出的物品） | 擊殺數與帶出的背包內容；不保存到下一局（pv8 5-5） | |

## 6. 誰看得到什麼

這題決定什麼：**複寫屬性分成公開／私人／事件三種通道的邊界**（README「網路協議升級」節），interest management 以哪個元件過濾。

| # | 問題 | 典型值 | 你的答案 |
|---|---|---|---|
| 6-1 | 哪些東西「所有人每 Tick 都要看到最新值」 | 視距內的玩家、AI、Boss 的身體與動畫；Boss 血量 | |
| 6-2 | 哪些東西「只有一個人看得到」 | 自己的背包、彈藥、冷卻、任務進度；開著的容器內容 | |
| 6-3 | 哪些東西「出現或消失時通知一次就好」 | 地上物品、容器、屍體、門的開關、放置物、Boss 換階段、擊殺訊息 | |
| 6-4 | 看不到的東西要不要送（防透視，pv8 2-3）；距離門檻 | 不送；玩家與 AI 視距 100 m、物品 30 m（pv8 4-3） | |
| 6-5 | 進房或重連時，要不要把世界上所有東西從頭送一遍 | 要；進房送一次基準（附錄 C 估 200 件約 7.3 kB） | |
