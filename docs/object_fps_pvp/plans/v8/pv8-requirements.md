# pv8 需求問卷：協議壓力點的玩法需求

更新：2026-10-30。Owner：`object_fps_pvp`。**狀態：先用典型值（`pv8-req-typical-values`）；之後可以逐題改。** 起因：`pv8-scope-reopen`（[HANDOFF](HANDOFF.md)）。

## 怎麼填

- 依 AGENTS §2「Feature → Contract → Architecture」，協議要先知道「要送什麼、送給誰、多少、多常」，才能決定通道與欄位。這份問卷只問玩法，不問做法。
- 每一題都有一個「典型值」，是參考 [協議壓力調研](protocol-pressure-survey.md) 填的假設。你可以：
  - 直接改數字或寫你的答案；
  - 寫「典型值」，照表上的值設計；
  - 寫「不做」，那一項就不進 pv8。
- 數字不必精確，量級對就夠（例如 50 和 200 會選到不同的做法，50 和 60 不會）。
- 填完之後的下一步：ultracode 的通道設計（另外徵求同意）。

## 1. 序號欄位（流水號）

協議裡的 tick、id、序號現在都是 uint64，帳面上每個 11 B（[多通道評估](multi-channel-evaluation.md) §1）。要定上限，需要下面的答案：

| # | 問題 | 典型值 | 你的答案 |
|---|---|---|---|
| 1-1 | 一個 Match 程序最長跑多久不重啟（決定 tick 的上限） | 7 天 | |
| 1-2 | 一個 Match 程序的生命期內最多幾位玩家加入過（決定玩家 id 的上限） | 65,535 | |
| 1-3 | 一位玩家一局最多送幾個動作（射擊、撿東西、技能……，決定動作 id 的上限） | 100,000 | |
