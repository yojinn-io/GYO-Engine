## 經過

1. **範圍。** 使用者決定 v6 納入四群（玩法／呈現、Engine 平台、驗收工具、Math 範圍外事項），規劃用 ultracode。
   第 6 項確認是自己死亡後仍看到第一人稱手臂，屬於缺陷。
2. **盤點。** 兩個 Explore agent 在 `05042fa` 逐項確認現況。HANDOFF 有幾處需要更正：
   - Engine 已經有 `PresentStatus::Skipped` 路徑。
   - 本機冷卻閘還有一道牆鐘閘。
   - FNV-1a 有三份，Color 的有限性檢查有五份。
   - 退化膠囊的 assert 在所有建置都會中止。
3. **初案。** 使用者要求先看一張批次、檔位、理由與職責的表，核准後才執行規劃。
4. **ultracode 規劃。**
   - 三個方案的組織原則不同：地基先行 23 批、垂直切片 18 批、以協議為中心 12 批。
   - 評審以「以協議為中心」案為主幹（評分最高），合成推薦案，原則是：
     - 量測閘門先行。
     - wire 只升一次，權威變更單獨成批。
     - Engine 工作與產品解耦。
     - 缺陷提前處理。
   - 評審也指出各案的事實錯誤，例如「Collision 統一同時影響射擊與移動」：已編譯的程式碼中，float 路徑只被 Match 的射擊使用。（後來依 D3 決定全部查詢共用單一容差，移動是否變化改為取決於 FF-9 的容差選擇。）
5. **對抗式檢查。** 6 個 major、12 個 minor，全部處理。主要的幾項：
   - **第 3 項的修法前提。** SDL 3.4.0 的 Metal 後端在不阻塞模式下只略過 fence，之後仍無條件呼叫 `[CAMetalLayer nextDrawable]`（`SDL_gpu_metal.m:3880-3908`）。這個呼叫最多阻塞約 1 秒，與 v5 的 1199 ms 吻合；長幀也仍回報 Presented。
     主對話讀原始碼確認屬實。因此 IP-2 改為先拆分量測，再選修法。
   - **Removability。** math-foundation HANDOFF 已把第 10 項的清單交給本產品的 HANDOFF；如果刪除本產品，Engine 的後續清單會一起消失。
     因此正式來源移到 Engine 計畫夾，並更新既有連結。
   - **證據缺口。** 唯一逐幀記錄第一人稱 `submitted_meshes` 的是 `weapon_short`，而第 5 項要刪掉它。第 02a 批要先把這個欄位移進存續的 probe，再刪除。
   - **漏列。** `run_native_window.py` 的「HP 歸零仍可移動、射擊」是同類的 v4 斷言，加入第 5 項。
   - **基線失效。** IP-2 改變幀節奏後，以 B0 比較就無法歸因。新增第 07 批重取 B1，並訂下基線世代規則。
   - **範圍。** include 風格統一屬於大規模 File Move，從整理批移出，改由使用者決定；結果是另立 FF-7。
6. **使用者決定。** 第一輪 18 項，見 HANDOFF 的決策紀錄。其中有三項比推薦更徹底：
   - 受擊欄位加帶攻擊者 id。
   - Collision「不想再埋坑」：全部公開查詢統一，並公開合法性檢查。
   - include 風格另立 FF 批徹底統一。
7. **v5 證據。** v5 的原始證據原本只在另一個 worktree。本批用 APFS clone 複製需要的 10 個目錄（1,325 個檔案），逐檔雜湊與原檔相同。

8. **落盤與審查。** 以一份最終規格為依據，6 個 agent 並行撰寫批次文件與兩個 Engine 計畫夾，2 位審查者檢查（一致性；事實與 AGENTS.md）。
   - 寫作者回報規格中的事實缺口，例如 `weapon_short.hpp` 還提供 `WeaponJson` 等共用 helper，以及版本號寫死處還有 `run_gameplay.py` 與 `backpressure_probe.py` 的 `b'\x08\x05'`。
   - 審查者找到的高嚴重度問題：
     - 第 05 批的 L1 斷言修正前也會通過：`submittedMeshes` 經過 `Alive()`。
     - IP-1 漏了同一幀內按下又放開的上升沿。
     - FF-9 與第 10 批對「移動是否改變」的說法互相矛盾。
     - FF-8 的 1200 bytes 歸屬前後不一。
     - 第 07 批與 IP-2 的完成條件互斥。
     - Engine 文件寫出產品名並連到本產品文件。
   - 使用者追加 D12（Engine 文件完全匿名、不連結）與 D13（IP-2 的 L2 在合併前完成）。主對話依既有決定定案：合併順序只是建議；FF-4 只收斂 render 內四份；1200 bytes 屬 Engine 傳輸契約；FF-9 的移動說法改為條件式；xhigh 只用在局部。
   - 修正後再驗證一次：252 個相對連結全部存在，Engine 文件沒有指向本產品文件的連結，沒有簡體字。剩下的 12 個小問題由主對話直接修正。
