# Engine FF-5：Ui 與 ui_editor 的重複、`item_step` 驗證

日期：2026-10-05。**完成**（PR 待開）。分支 `claude/engine-ff5`，疊在 FF-6 上。
計畫見 [基礎後續整理 PLAN 的 FF-5 節](../architecture/plans/foundation-followups/PLAN.md)。scratch 比對的結果在 [HANDOFF 的 FF-5 節](../architecture/plans/foundation-followups/HANDOFF.md)。

## 開始

接續使用者「把 Engine 側的功能完成」的指示。檔位 high（`item_step` 契約部分 medium），不用 ultracode。

## 做法

1. **Ui 公開既有規則**（`ui/UiRuntime.hpp`，與 `HitTestUiLayout` 並列）：
   - `FitDesignCanvas(designSize, viewport)`：原本 UiRuntime 內部的 `MakeFit`（統一縮放、置中）。
   - `ContainsUiPoint(rect, point)`：原本內部的 `ContainsHalfOpen`（半開區間，空矩形不命中）。
   - `AlignUiText(bounds, extent, horizontal, vertical)`：原本 UiRenderer 與 ui_editor 各寫一份的文字對齊。
   運算式與原本相同、順序相同（建置關閉了 FP contraction），所以結果逐位元相同。
2. **改用**：
   - UiRuntime 的 fit 與命中判定、UiRenderer 的文字位置。
   - ui_editor `PreviewAdapter.cpp`：選取框外框的 letterbox 父矩形、預覽的 viewport 內判定、文字位置。
3. **單一走訪**：UiRuntime 的 `EvaluateElements` 與 `ComposeElements` 合併成 `WalkElements`，以 visitor 處理差異：
   - Evaluate 推入 evaluated element；
   - Compose 做負尺寸檢查與繪製（`ComposeElement`）。
   走訪順序（元素、list 項目、子元素）與錯誤順序都和原本相同；list 項目同時帶 `UiListItem*`（文字用）與 index（layout 用）。
4. **`item_step`**：`UiValidation` 的 `fixed_step_list` 檢查 `item_step` 有限（float 值），錯誤位置 `…/item_step`。codec 以 double 讀 JSON 再轉 float，所以 1e39 會變成 inf 而被拒絕；最大有限 float（3.4028234663852886e38）仍可載入。
   不升 `kUiSchemaVersion`；`docs/ui_toolchain.md` 的 JSON v1 節註明規則。

## Architecture Delta（Editor／Runtime Data Contract，依計畫）

- Data Contract：gyo.ui 的 Validation Rule 新增 `item_step` 有限性（版本不變，契約文件已更新）。
- Engine Ui 公開三個既有規則；layout 規則歸 Engine Ui，ui_editor 只呼叫。依賴方向維持 Editor→Engine；Runtime 不依賴 Editor。
- Fitness：刪除 ui_editor 後，Runtime 仍能讀取既有有效資料（規則在 Ui 內）。
