## 實作與設計

| 位置 | 第 04 批的責任 |
|---|---|
| `PvpApplication.cpp` | 資產準備、原生事件邊界、單次提交、本機回饋、權威 HUD、生命週期清理 |
| `PvpApplication.hpp` | WeaponFeedback 與成功 Presented 的只讀證據，不含測試控制 |
| `App/WeaponViewModel.hpp/.cpp` | 產品呈現專用 Idle／Draw／Shoot frame、資產時長、視覺後座與姿態觀測 |
| `App/WeaponPresentationDefinition` | 依實際槍模 placement 計算呈現槍口；不參與 Match 射線 |
| 產品 CMake／project.json | Client 所需 Model／ModelRenderer／SDL_IMAGE／UFBX，三個既有呈現來源 |
| 產品 acceptance | SDL 輸入、真 GUI 呈現／GPU 圖像、顯式短模式及證據分析 |

1. **Join 前準備槍模。** 重用 `object_fps_pvp.weapon.mark23`、現有 FBX、Hand／
   Glove／Mark23 三張材質及動畫。InitializeGraphics 載入 CPU／GPU 資源，再成功
   Render 一次 Idle，暖機與 Shoot 共用的 lazy pipeline；第一槍不載入資產。
2. **每個合法上升沿提交一次。** 原生事件保存單幀 edge；先消費一幀滑鼠 delta、
   更新絕對 yaw／pitch，再在移動固定步之外呼叫 SubmitShot。只有 optional ID
   成功才播放一次 Shoot。按住、冷卻預判、窗口滿不產生缺號或未送出的動畫。
3. **捕捉與射擊分開。** 首次 click 或 Tab 取得捕捉的整幀不開槍。失焦、移動／
   縮放／最小化視窗清 pending edge 並釋放滑鼠；Tab 釋放所在幀亦阻止後續 click
   立即重抓。這個同幀邊界已由短測覆蓋。既有待裁決操作照常由 worker 保存。
4. **後座不改瞄準。** Shoot 動畫與短暫 kick 只作用於專用 ViewModel placement／
   深度層；相機、原始 mouse delta、已提交命令及權威射線不受影響。動畫時長讀
   FBX clip，冷卻讀 Match CombatRules，不接 Campaign WeaponController／彈匣。
5. **結果與狀態各自呈現。** 同一次 Drain 消費裁決；接受且命中玩家才顯示標記，
   拒絕顯示短狀態，重送／ACK／replay 不重啟動畫。HP／權威冷卻只取最新 combat
   快照，晚到裁決不倒退 HP。HP=0 仍可操作；Esc 重入新身分時清動畫／提示／計數。
6. **只讀觀測與正式操作分開。** WeaponFeedback 記本機提交、動畫、裁決、姿態、
   HP、同機時間；成功 Render 後才複製到 PresentedMovement.weapon。同幀 ID 對應
   真實提交，skipped frame 不複用舊樣本。測試注入與錄影／圖像保存都只在 probe。

AppSupport 新增的 API 是產品內的呈現值；原有 WeaponPresentationSnapshot overload
保留，public header 以 forward declaration 避免強迫 PvP 引入 Campaign 型別。
只有三個呈現 cpp 納入 Client，沒有把整份舊 APP_SUPPORT／APP_DOMAIN 列表編入。

## 驗證順序與結果

先建置 Client／產品測試，再建置 GUI probe；先單獨跑一次八秒 60 FPS 雙 GUI，
通過後凍結產品實作，執行五案短矩陣。沒有執行 120 秒 GUI 或 30 分鐘長測。

| 檢查 | 結果 |
|---|---|
| PvP domain／Model／ModelRenderer／UFBX／Component／ProjectComposition | 六項通過；PvP 97 cases／1,390,416 assertions |
| 實際 GPU smoke | Vulkan／SPIR-V，vertex update、ViewModel depth、culling、UV、projection、blend、color 全通過，0.88 秒 |
| 呈現分析器 | 16／16 通過，6.687 秒；短跑不能冒充 120 秒完整跑次，未配對事件仍計入分母 |
| 真雙 GUI | 五案通過：weapon30、weapon60、weapon144、capture、latency |

初次 core CTest 的 GPU 項因 sandbox 無法存取桌面而報 SDL video initialization
failed；六項 CPU 均通過。授權存取桌面後只重跑該 GPU 項並通過，未掩蓋原失敗。
GUI probe 初次建置另修正一處未限定 namespace 的測試型別，沒有更改產品語意。

### 操作與射擊呈現：30／60／144 FPS

每種 FPS 跑次八秒，兩個真實 Client 視窗經現有 SDL adapter 驅動，連接真正的
Match／Gateway。每案驗證六次操作者 SDL 射擊及一次 HP=0 對手射擊，另有一個
明確的直接 API 請求驗證權威冷卻拒絕；後者不計成本機動畫或 SDL 射擊。

| 名義 FPS | 操作者／對手實際 FPS | 成功呈現間隔 P95（兩端） | 每槍提交至首次成功 Presented 範圍 |
|---:|---:|---:|---:|
| 30 | 29.94／29.93 | 34.37／34.14 ms | 1.74–2.29 ms |
| 60 | 59.64／59.66 | 17.44／17.27 ms | 1.60–2.62 ms |
| 144 | 142.04／142.14 | 7.64／7.51 ms | 1.59–2.51 ms |

FPS 表使用事先指定的 0–5 秒遊玩窗口，包含全部慢幀，不依幀快慢挑選。完整
Update 幀、世界成功呈現間隔與 lifecycle 資料另全部保存。三案共 **21 次 SDL
射擊** 都在下一個成功 Presented 幀顯示，不等裁決；這是 SubmitShot 後至 renderer
返回的時間，**不是硬體點擊延遲、GPU scanout 或 input-to-photon**。

覆蓋：首次 click 只捕捉、按住只一槍、一幀多移動固定步不重複射擊、四次命中
歸零、牆壁遮擋、冷卻拒絕、HP=0 仍移動／射擊、移動＋轉向＋射擊 mouse delta
只用一次、失焦／Tab／window moved 無幽靈射擊、Esc 離開後重入滿血且無舊效果。
命中標記由權威 Player hit 觸發，拒絕／World hit 不偽造 Player hit。

八秒操作計時區間內，三案 update loop 最大間隔分別約 33.54／16.90／7.43 ms，
零 renderer skipped。Join／暖機的原始幀亦保留；144 FPS 跑次全程最大為約 20.15 ms。
操作者跨 Esc → Lobby → 新身分之「世界樣本」最大間距為 102.33／52.28／43.91 ms，
原值保留；Lobby 仍渲染 UI，但沒有世界 PresentedMovement，不能將該間距稱為
GPU 停頓，也不能從原始結果抹除它。

### 跨視窗真實移動呈現

顯式 `--latency-short`：兩秒暖機、16 秒／20 個預先排定移動事件、末尾兩秒配對；
只有成功 Presented 的同幀本機／遠端位置參與計算，計時期間無 readback／存圖。
`PushMovement` 只在未捕捉時注入 capture click，避免升級後每次起步意外開槍。

- 20／20 配對、零無限延遲事件；nearest-rank P50 **48.43 ms**、P95 **48.84 ms**。
- 既有門檻 P50 ≤50 ms／P95 ≤80 ms 與配對率 ≥99% 不變，缺失／不明仍計無限延遲。
- 兩端實際 59.67／59.68 FPS，呈現間隔 P95 約 17.13／17.15 ms，最大 17.50／
  17.47 ms，零 skipped。完整 trace 與命令歸因仍在證據中。
- 這支持本批的**短呈現回歸通過**；不宣稱與舊跑次做出統計等價性證明，也不取得
  120 秒／200 事件完整跑次資格。原 long 模式及門檻保持原樣。

### GPU 圖像核對

另起 capture 跑次，與延遲計時分離。保存 Draw、Idle、Shoot、960×540 → 1120×630
縮放及靠牆五張 SceneCapture BMP；為閱讀產生無損 PNG 副本，原檔保留。
實際每幀提交五個模型 mesh、三個 material；Shoot 樣本為約 67 ms 的動畫姿態，
視覺 kick 約 0.0156 radians。已目視核對槍／手套／手臂材質、姿態差異、縮放比例
及靠牆時獨立 ViewModel 深度；GPU smoke 另驗證深度／投影／顏色像素。

SceneCapture 在 UI 之前，圖像不包含 HUD；HUD 的 HP、標記與拒絕狀態由同幀
Presented 觀測及 UI submit 成功核對。不是人工拖曳標題列／OS 視窗管理員的重現。

## Architecture Delta 與未完成範圍

- **壓力／必要性：** 本機回饋必須早於裁決，且不能受移動 replay 重播。原 Campaign
  snapshot 含彈匣型別，故增加產品內的 presentation-only frame，沒有新通用框架。
- **邊界／依賴：** Client 增加既有 Engine Model／ModelRenderer／圖片能力；動畫、
  recoil、HUD 由產品擁有。Match／Host／Gateway 不認識模型或動畫，Engine 不反向
  依賴產品。無新 Top-level、跨產品依賴、內容格式或 wire 變更。
- **Fitness：** 產品 CMake／registration 宣告依賴及 acceptance role；公共 build、
  Engine、services 無修改，Component／ProjectComposition 短測通過。未重跑完整
  刪除副本，不能把靜態邊界檢查當成完整移除驗收。
- **網路基線：** Match SHA `29f64b3cf1957cffbc6cda6ee3c324fa5eb0a0a741c148161f50554b8ee70ac5`、
  Gateway SHA `ff4e4c7d162caa59cb10c72c935e1566ec874ce2225396dd69c60859bd5db554` 與第 03 批相同。
  ClientConnection／權威來源未改，重用第 03 批共存／恢復及 Go race 證據，不無故重跑。
- **限制：** 16 秒短回歸不能替代完整 GUI 或長測；未測實體 LAN、Windows、人工
  標題列拖曳或 monitor scanout。原 OS 整機停頓根因仍未證實，v4 仍無命中回溯。
  第 05 批整合驗收與手動指南留待使用者指定；未改舊 v3 release manifest。
