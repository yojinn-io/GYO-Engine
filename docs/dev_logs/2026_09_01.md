## Architecture Audit

確認並修復的真實壞味道：

- README 將尚未存在的 Editor、Scene、Audio、Physics、Systems 等願景混寫成現況。
- Runtime 原本直接混合 Win32、SDL、ImGui、JSON、主迴圈與 renderer lifecycle。
- `platform/` 願景混淆 OS/window 與 DX12/Vulkan graphics backend。
- `systems/` 以「每幀更新」分類責任，且存在大量空 placeholder。
- Editor、Game、Framework、Tools target 只有空殼，Editor 還反向依賴 Runtime。
- SDL、ImGui、doctest 等 dependency 原本無條件加入。
- Asset path 可透過 `..` 逃出 asset root。
- `AssetId`、`AssetType`、Input Action/Axis ID 的 identity、equality、hash 規則不一致。
- Asset reload、stale handle release、eviction 存在 generation resurrection/ABA 風險。
- Engine tests 曾依賴 Object_FPS asset，破壞 reusable Engine 邊界。
- 沒有中立的 Query/Command/Event runtime seam。

## Responsibility Corrections

| 修改前 | 修改後 |
|---|---|
| Runtime executable 擁有所有 SDL/ImGui 行為 | `RuntimeLoop` 管 phase；Platform、Input、Render adapter 各自負責 |
| SDL、DX12、Vulkan 都被視為 platform | SDL window/event 在 `platform/sdl`；graphics implementation 在 `render/backend` |
| `systems/` catch-all | Input 已獨立成 `input/`；其他責任待需求出現再建立 |
| AssetManager 周邊責任模糊 | Manager 管 identity/cache/lifetime/dispatch；Source 管 IO；Loader 管 decode；RenderDevice 管 GPU upload |
| Object_FPS/KamataEngine framework | Object_FPS 直接消費 GYO 公開 contracts |
| App state 只能由內部直接操作 | typed `IRuntimePort<Snapshot, Command, Event>` 提供中立 seam |

## Final Dependency Model

```text
Object_FPS / Game / Test / External Controller
                    |
        GYO public runtime mechanisms
     Runtime / Input / Asset / Render
                    |
       Platform and render adapters
                    |
        SDL / SDL_image / SDL_GPU
```

禁止方向經掃描確認為空：

```text
GYO Core -X-> Object_FPS
GYO Core -X-> KamataEngine
GYO Core -X-> Weaver
Game domain -X-> D3D12/Vulkan/SDL GPU resources
```

SDL_GPU backend 也能在沒有 Runtime、Object_FPS、Input、SDL_image、ImGui 的組態下單獨建置。

## Runtime Boundary

目前最小 seam 是：

- `Query()`：借用當前 immutable typed snapshot。
- `Submit()`：提交 runtime 驗證與執行的 typed intent。
- `Events()`：讀取當前 advance 產生的 typed facts。

[ObjectFpsRuntimeClient.cpp](D:/code/Source/GYO-Engine/apps/object_fps/src/App/ObjectFpsRuntimeClient.cpp) 同時實作 `IRuntimeClient` 與 typed `IRuntimePort`。介面沒有 SDL、D3D12、GPU resource 或 caller identity。

這只是 Weaver-compatible architecture seam；沒有實作 Weaver、Weaver adapter、因果圖或敘事系統。

## Remaining Risks

- 視窗最小化且 present skipped 時，RuntimeLoop 可能高 CPU 空轉；應由 app/backend-aware pacing 解決。
- async `ForceReload` 成功後，enqueue 時取得的 handle 會 stale；未來宜分離 reload token 與 asset handle。
- Object_FPS CPU decoded texture 與 GPU texture 目前同時常駐，內容規模擴大後需要 residency policy。
- `GYO::Engine` target 仍同時包含 Base、IO、Asset、Runtime；未來規模變大時可再依真實 consumers 拆 target。
- SDL_GPU presentation 現階段只驗證 Windows/MSVC。
- Audio 尚未實作，因此本輪沒有宣稱通過 audio vertical slice。
