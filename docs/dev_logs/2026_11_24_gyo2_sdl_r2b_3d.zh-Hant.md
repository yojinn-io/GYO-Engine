# 2026-11-24 SDL 線子批 R2b 的 3D 段：3D pass、合成、`mesh_render`、CPU 蒙皮（`v8-arch-gyo2-sdl-r2b-3d`）

Owner：架構。GYO2 主會話開的 R2b 任務卡的第二段（第一段是 2D，[dev_log](2026_11_24_gyo2_sdl_r2b_2d.zh-Hant.md)、PR #319）。分支 `claude/gyo2-sdl-r2b-3d`，疊在 2D 段之上（開向 `gyo2`）。作者 Opus 5.5／high；`sdl_gpu` 的 3D 後端由子 Agent（Opus／high，另一個工作樹）寫、合進本分支。
根據：[SDL 總宣告](../architecture/target/v2/sdl-declaration.zh-Hant.md)第 6.1 節第 8 點、6.4、10.2 節的 R2b 列；PvP 盤點（`games/object_fps_pvp/docs/porting-inventory.zh-Hant.md` 第 2.3 節 R2b 列、PV5、PV7、第 4.6 節）；model（#313、#317）的資料與第 2.1 節的蒙皮式；`-skeletal-animation-layers`（第 3 層歸 render、GPU 或 CPU 在 R2b 判）。照新 AGENTS 不另寫事前宣告；取捨在 [render](../architecture/target/v2/render.zh-Hant.md) 第 8 節。

## 做了什麼

1. **`render` 的資料**：`RenderCommands::passes` 改成 `std::vector<RenderPass>`（`std::variant<Pass2D, Pass3D>`）；`Vertex3D`、`MeshId`、`CullMode`、`Draw3D`、`Pass3D`；`RenderMeshes`（資料側配 id 的保留網格，`render_world` 登記、`Cleanup` 清要求）；3D pass 的 HLSL（`mesh3d.*.hlsl`、`Mesh3D.hlsli`，unlit）與 `ShaderAbi.hpp` 的 `kMesh3D*`。
2. **合成**：`Compose.hpp`——`camera_render` 的 `CameraPasses`（每個相機一格）與 `ComposeCameraPasses`（`PostUpdate`）照相機順序寫進 `RenderCommands`、每個相機的清除在前（2D 段 `Queue2d` 裡的清除邏輯搬到這裡）。
3. **3D 管線**：`Pipeline3d.hpp`——`Extracted3dItems`、`RenderModelMeshes`（模型網格為鍵）、`MeshVertices`、`SkinVertices`（CPU 蒙皮）、`PlaceMesh`、`Queue3d`（不透明近到遠、半透明遠到近、不測深度的最後）。
4. **可畫元件**：`Mesh3d`、`SkinPose`（`world_render` 登記）；`render` 的依賴加 `model`（只取型別）。
5. **新列 `mesh_render`**（渲染側）：`ExtractMeshes3d`、`Queue3dPasses`。`sprite_render` 改成往 `CameraPasses` 放。
6. **`RenderImages` 搬到 `render_world`**：2D 與 3D 共用；作者持有的圖沒人用就放掉的那一步改在 `Cleanup`（清完要求之後），不依賴兩個管線的 extract 誰先跑。
7. **`sdl_gpu`**（子 Agent）：`Pass3D` 的 render pass（深度格式 D32→D24→D16 選第一個支援的、深度每個 pass 清成 1、顏色載入）、pipeline 的 key（格式、blend、depthTest、depthWrite、cull）、保留網格的 GPU buffer、`Submit`／`Capture` 多吃 mesh 要求、`SDLGPUStatus` 加 mesh 的計數；`render` 加 `ViewportOf(const Pass3D&, TargetSize)`；SDL 頁第 7 節加 3D pass 一條。
8. **測試**：`render.pipeline3d`（`Queue3d`、蒙皮、保留網格、節點、合成）、`render.extract` 加「3D 相機的網格（真的 FBX 經 world_asset）→ HUD 相機的 sprite 照相機順序」；`sdl_gpu.pass3d`（子 Agent：Metal 上 10 個 case、102 個 assertion，含深度、cull 的螢幕方向、保留網格、2D→3D→2D 的 buffer 順序、World 替換）；2D 段的測試跟著合成改。
9. **突變**：render 加 `p3-`／`cp-` 17 個、`rd-mesh-release-kept-live`、`g3-` 33 個（子 Agent）；拿掉被合成取代的 `p2-later-clears-target`、`re-every-camera-first`；`re-held-not-ended` 跟著搬到 `render_world`；`rd-tex-release-kept-live` 的 `find` 因 `RenderMeshes::Release` 用了同一行而不唯一，改寫。
10. **文件**：render 頁第 2、7 節的清除、新第 8 節、RD-8、RD-9、RC-RD 6、範囲の限界；model 頁第 3 層定 CPU。

## 卡片判的（理由在 render 頁第 8 節；可推翻）

| 題 | 定法 |
|---|---|
| 蒙皮 GPU 或 CPU | **CPU**：來源側的介面（`SkinPose`）兩種做法一樣、上層不依賴；PvP 的量小（4 個身體＋1 個 viewmodel）；換 GPU 的條件 RC-RD 6 |
| 2D 與 3D 的先後 | 照相機的 order 合成（`camera_render` 的 `ComposeCameraPasses`）；`RenderCommands::passes` 改成 variant |
| viewmodel 的「清深度」 | 每個 `Pass3D` 自己的深度從清空開始（同 Bevy 每台相機自己的深度），不另設旗標 |
| 3D 的實體對應 | 網格每幀暫時；保留的是模型網格（素材 id、life、網格索引為鍵）；沒有渲染側實體 |
| 著色 | unlit（同 master）；PBR、材質系統、後處理（exposure／gamma）、MSAA、陰影不在本批 |
| 模型的材質 | 作者讀 `Material` 填 `Mesh3d::color`／`image`；不自動解析 |
| cull | `CullMode::Back`＝螢幕上順時針的不畫（逆時針為正面，同 Bevy 的 `FrontFace::Ccw`），預設 `None`；Metal 上像素測試確認，Vulkan／D3D12 由 L1 看 |

## 本機驗證

- macOS Intel（Metal）：`ctest -L 'cpu|gpu|shader'`（排除本機離線設定造成的 `cmake.PluginSelection`）全部通過。
- Vulkan（Linux Lavapipe）與 D3D12：本機沒跑，看 L1。

## 交使用者的

- 沒有。本批沒有推翻使用者決定的條文。PvP 盤點列在 R2b 的「後處理（exposure／gamma）」沒有做，記在 render 頁範囲の限界，交 PvP 移植時定。
