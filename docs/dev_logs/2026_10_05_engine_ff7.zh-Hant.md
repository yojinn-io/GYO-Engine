計畫見 [基礎後續整理 PLAN 的 FF-7 節](../architecture/plans/foundation-followups/PLAN.md)，紀錄見 [HANDOFF 的 FF-7 節](../architecture/plans/foundation-followups/HANDOFF.md)。

## 開始

使用者指示「先把 Engine 的任務清了」，並決定：

- 方向：`engine/<m>/`。
- 順序：FF-7 先於 IP-2。IP-2 的程式還沒開始，搬移在沒有其他程式變更進行時最乾淨。

檔位 high。計畫建議大範圍掃描用 ultracode，這次沒有使用：

- 盤點與改寫用腳本，只取代「舊路徑恰好是搬移前實際存在的 Engine header」的 include，不用前綴猜測。
- 完整性由建置、CTest 與兩樹比對外部驗證。

## 做法與結果

1. **盤點**：
   - 11 個非 `engine/` 前綴的公開根目錄、30 個 header。
   - 全 repo 有 254 行 include 指向它們：
     - 160 行在使用中的程式（Engine、`tests/common`、ui_editor、提出需求的消費端）。
     - 94 行在未啟用產品。
2. **規則**：header 路徑＝`engine/`＋模組在 `engine/` 下的目錄。例如：
   - `render/Renderer.hpp` → `engine/render/Renderer.hpp`
   - `render/backend/sdl_gpu/SdlGpuRenderDevice.hpp` → `engine/render/backend/sdl_gpu/SdlGpuRenderDevice.hpp`
   - `model_renderer/ModelRenderer.hpp` → `engine/render/model/ModelRenderer.hpp`（target 仍是 `gyo_model_renderer`）
   - `platform/sdl/SdlPlatform.hpp` → `engine/platform/sdl/SdlPlatform.hpp`

   CMake 的 include 目錄（各模組的 `include`）、target 名稱、namespace 都不變；只在 `include/` 下多一層 `engine/`。不留別名或轉送 header。
3. **改寫**：`git mv` 30 個 header；83 個檔案、160 行 include。另外更新 `tests/common/math/MathCharacterizationTests.cpp` 註解中的 3 個 header 路徑。
   - 消費端裡尚未刪除的未編譯檔也一起改，讓使用中的程式 grep 為 0。
   - 未啟用產品不改，對應表寫進[遷移清單](../architecture/plans/foundation-followups/inactive_products.md)。
4. 文件中的歷史紀錄（dev_log、已結束計畫的 baseline、各計畫已寫下的檔案位置）保留原路徑，不改寫歷史。
