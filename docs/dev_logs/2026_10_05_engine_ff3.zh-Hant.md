# Engine FF-3：FNV-1a 收為一份

日期：2026-10-05。**完成**（PR 待開）。分支 `claude/engine-ff3`，疊在 FF-2（`claude/engine-ff2`）上。
計畫見 [基礎後續整理 PLAN 的 FF-3 節](../architecture/plans/foundation-followups/PLAN.md)。

## 開始

使用者離開前指示「把 Engine 側的功能完成」。檔位 high（計畫建議值，等於主對話檔位），不用 ultracode。

## 做法

1. **先鎖舊值**（在舊實作上通過後才改實作）：
   - `AssetId::FromString("")`＝`0xcbf29ce484222325`、`AssetId::FromString("player_tex")`＝`0xb52b0c137347c8a6`。
   - `AssetType` 六個標準型別的值。
   - `InputActionId::FromString("fire")`、`InputAxisId::FromString("move_forward")` 的值；空字串仍為 0（無效 id）。
   - ui_editor 的 `ProbeFileStamp`：內容 `foobar` 的 `contentHash`＝`0x85944171f73967e8`。
2. **Base header**：`engine/base/include/engine/base/Fnv1a.hpp`，`Engine::Base::Fnv1a64(std::string_view)`，constexpr、只依賴標準庫。
   測試 `tests/common/base/Fnv1aTests.cpp`：公開參考向量（空字串、`a`、`foobar`，含 `static_assert`）、`\0`、`\xff`、UTF-8 的 `é`（涵蓋 signed char 平台）。
3. **三處改用**：`AssetId.hpp`、`AssetType.hpp`（標準型別改傳字串字面值，不再手寫長度）、`InputActionMap.cpp`（空字串→0 的規則留在 `HashName`）、ui_editor `FileService.cpp`。
4. **刪除** `engine/asset/include/engine/asset/detail/Hash.hpp`，不留轉送 header。其中的 `HashCombine` 沒有任何使用者，一起刪除；`Engine::Asset::Detail::Hash64` 別名也只在該檔使用。

## 驗證

- CTest 55／55（macOS Intel）。characterization 與參考向量都通過。
- 依賴邊：以 `cmake --graphviz` 比較 base 與 branch，只新增 `gyo_input→gyo_base`（宣告的那一條），沒有刪除的邊。
- 未啟用產品：grep `apps`、`tools`、`tests`、`build/acceptance` 沒有使用 `Detail::Fnv1a64`、`Asset::Detail` 或 `detail/Hash.hpp`。
- 平台：CI 四平台由 PR 的 CI 驗證；Windows、Linux、macOS arm64 實機未執行。

## Architecture Delta（依 AGENTS §3，與計畫一致）

1. 需求：FNV-1a 重複（三份）。
2. 問題：同一演算法三份；asset 的那份在 `Detail` 命名空間，其他模組無法正當使用。
3. 邊界：`GYO::Base` 新增公開 header `engine/base/Fnv1a.hpp`；asset 的 `detail/Hash.hpp` 刪除。
4. 影響：`engine/base`、`engine/asset`、`engine/input`、`tools/ui_editor`。
5. 依賴方向：新增 `gyo_input→GYO::Base`（PRIVATE）；Base 是最底層、header-only。
6. Ownership：雜湊歸 Base；空字串為無效 id 的規則歸 `InputActionMap`。
7. 更小的替代：見計畫（放 asset 會讓 input 依賴 asset）。
