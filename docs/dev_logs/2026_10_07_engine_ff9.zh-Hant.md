# Engine FF-9：Collision 統一與公開合法性檢查

日期：2026-10-07。**完成**（與提出需求的消費端的權威變更批同一個 PR #58，2026-10-07 合併，`7226ca0`）。計畫見 [FF-9](../architecture/plans/foundation-followups/PLAN.md)，事前宣告、修訂與事後量測見 [記錄器](../architecture/plans/foundation-followups/HANDOFF.md) 的 FF-9 節。

## 經過

1. **事前宣告**（實作前）：以 ultracode 規劃（3 份草案、1 位評審、1 次對抗檢查），使用者核准。容差 `1e-7`；結果會變的公開函式只有 `RaycastAabb` 與 `VerticalCapsule` 版的兩個；FF-1 語料恰好 435 筆不同。
2. **方向修正**（使用者，實作前）：「退化膠囊一併拒絕」改為「退化膠囊造成的中止一併消除」。`IsValid(VerticalCapsule)` 沿用現行 double 驗證（height ≥ 2r，球合法），並公開 `IsValid(Math::Capsule)`。理由：中止只發生在 float 路徑，FF-9 刪除它之後就不存在。
3. **commit 0**：語料分析器擴充（`--check equal`、`--check ff9`）並凍結；自我檢查與宣告一致。
4. **commit 1**：公開 4 個 `IsValid`，內部 assert 改用；合法輸入集合不變，語料全等。
5. **commit 3**：`RaycastAabb` 改為 double slab；`VerticalCapsule` 版改為 `Math::Capsule` 版的薄包裝；刪除 float 演算法與兩個 1e-6 門檻；`Collision.hpp` 記錄數值語意。

## 結果

- 語料：恰好 435 筆不同，翻轉方向、ULP 分桶、最大 ULP 都與宣告逐項相同；`RaycastAabb` 等於精確參考、`/vertical` 等於 base 的 `/general`、其餘 11,215 筆逐位元不變。
- 靈敏度：容差改為 1e-6 時恰好偵測到宣告的 16 筆（scratch，不提交）。
- `--degenerate`：25 個全部合法、全部執行。
- 消費端的權威 digest 不變（由消費端記錄）。
- CTest 61／61。

## Architecture

見 PLAN 的 FF-9 Architecture Delta。公開 API 新增 4 個 `IsValid`；公開簽名、回傳型別與 Contact 結構不變；合法輸入集合只在射線方向上放寬（任何非零的有限方向）。未啟用產品的影響見 [遷移清單](../architecture/plans/foundation-followups/inactive_products.md)。
