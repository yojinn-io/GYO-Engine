## 突變清單的敵對式檢查與兩個缺陷

- Fable 5.2／high（`trace-mutation-adversarial-fable.md`，候選 `trace-mutation-adversarial-fable.extra-mutants.json`）：正式清單 31/31、2/2 killed；候選 48 個裡 41 個存活，歸成 2 個缺陷、19 處測試缺口、4 個不建議加、5 個等價。
- **F1**（實作沒照 D4 (i)）：同步點與 hook 清空輪裡被拒絕的 hook 已經經 `Fail` 標過 origin，同步點的 `Fail` 又標一次 origin，一個錯誤兩筆路徑。修法：同步點、清空輪的 `Fail` 在 `leftError_` 已經有值時只標「經過」（和 System 那一步同一個判法）。先 Red（`trace-f1-f2-red.txt`）。
- **F2**（實作沒照 D4 (i)）：DropOldFirst 的替換在編排層自己的步驟失敗時，錯誤帶著 `failure`，被 `PassesThrough` 當成經過，一筆路徑都沒有。修法：`PassesThrough` 只看碼——`ScheduleFailed`、`ReplaceScheduleFailed`（Kernel 標過）與 `WorldInterrupted`、`WorldMissing`（Product 已經結束）是經過，其餘是 origin。先 Red。
- 兩個都是本批的實作照核准的宣告修正，不改契約。
- 測試缺口：條文寫明的都補了測試與突變（trace Module 10 案、Kernel 3 案、編排層 3 案、日誌 1 案、情境 S4-1 一個判定）；「不建議加」的 4 個與「等價」的 5 個照報告不加。`MarkError` 送給現在的接收者（宣告沒約定）、路徑紀錄的 `world`（TR-5 沒列）兩件沒加，記在合併前核准頁。

## 審查（Fable 5.2／high）與修正

- 報告 `trace-review-fable.md`：必改 1、建議改 5、小問題 6；審查者在自己的工作樹跑 ctest 156/156，Windows、Linux 只讀。
- **必改 1**：F1 沒修完。trigger 的兩個出口（`TriggerFromHost` 與 System 當下觸發）在清空輪裡被拒絕的 hook 已經標過 origin 時，用預設的 origin 再標一次。修法同 F1（`!world.leftError_.has_value()`），Kernel 補兩案（`[ks-trace-host-trigger-once]`、`[ks-trace-system-trigger-once]`）。
- **建議 2**：子段的例外被接住後，父段的 `childUnwound` 不清，父段自己的例外沒有路徑。父段開始新的子段或被標記時清掉；兩件都沒有就自己丟例外的情形寫進 TR-3。
- **建議 3**：category 超過 64 位元組時 `GYO_ASSERT`（`noexcept` 的路上，而且是替外面決定處理）。改成截斷，寫進 TR-5。
- **建議 4**：段開著時 Logger 卸下，結束時段紀錄寫到標準錯誤。`WriteSpan` 先再問一次 `Taken`。測試讀不到標準錯誤（OS 邊界守衛），改用「結束時沒讀時鐘」判；第一版用記憶體輸出端判，拿掉修正也通過（Red 沒成立），改寫後才 Red。
- **建議 5**：給的欄位已有 `trace_path` 時，致命紀錄同一個鍵寫兩次。已有就不加；LG-2 的文字同時改成照實作的「路徑非空時」。
- **小問題**：7（安裝的前提）寫進 TR-7；8（超過 64 層的標記丟掉）寫進 TR-4；9（段在別的執行緒結束）寫進 TR-4 與 RC-T1；10 改成 `constinit thread_local Stack stack{}`；11、12 寫進合併前核准頁第 4、5 節。
- Red 全部在 `trace-review-red.txt`；修正後本機全量 ctest 156/156（`trace-review-ctest.txt`）。
- Windows 的 L1 曾因 doctest 印 `std::string_view` 要 `<ostream>` 而編譯失敗（C2027），新的四個測試檔補上（88e41a5f）。

## 和宣告不同的地方

- `Trace::Install` 回 `TraceHandle`，不回 `Result`：沒有會失敗的路（宣告 D8 寫 `Result`）。
- 路徑的分隔用 ASCII 的 ` > `（宣告第 1 節的例子寫 `›`），主控台與各平台的終端機都讀得出。
- 致命紀錄的 `trace_path` 在給的欄位超過 32 個、或已有 `trace_path` 時不加（固定大小的陣列，不配置；鍵只出現一次）。
- 編排層五個入口的本體改名成私有的 `…Steps`，公開的入口變成包一段的薄包裝（宣告 D6 沒寫做法；選這個是為了不必把 `ReplaceWorld` 的兩百行重新縮排，和第 4 批改同檔時衝突最少）。
- 宣告 D8 的 `options.clock`，實作是 `TraceOptions{monoNs}`（函式指標）。
- 宣告的登記列寫 `base;logging,time`，實作是 `depends`＝`base`、`private_depends`＝`logging;time`（宣告寫錯了欄）。
- category 最多 64 位元組、超過截斷（宣告沒寫上限；實作原來是斷言，審查後改）。
- Kernel 的同步點、清空輪、trigger 兩個出口的 `Fail`，在 hook 已留下錯誤時只標經過（F1 與審查必改 1）；編排層的經過只看碼（F2）。
