# 2026-09-15：Mark-23、跳躍與共用門材質

> Historical record: this document preserves the implementation, commands and results from its original date. Paths and ownership may predate the current architecture; use [the current architecture](../architecture.md) and [build guide](../creating_apps.md) for present instructions. These results do not validate later revisions.

## 本輪目的

以 GYO 內的 Object_FPS 作為可移除的驗證遊戲，加入能辨認的白色門、
玩家膠囊真正離地的跳躍，以及帶手臂的 Mark-23 骨骼動畫。

| 責任 | 所屬 |
|---|---|
| 獨立根目錄的 catalog 合併、ID 與資產生命週期 | Engine Asset |
| FBX bytes 解碼、座標／單位轉換、動畫烘焙 | 可選 GYO::AssetUfbx |
| 模型／骨骼／片段資料、姿勢取樣、CPU 蒙皮 | GYO::Model |
| 直立膠囊、射線與球體掃掠數學查詢 | GYO::Collision |
| 動態頂點更新、獨立 ViewModel camera/depth | GYO::Render 與 SDL_GPU backend |
| 起跳條件、重力、地圖阻擋、彈藥、裝備與傷害 | Object_FPS gameplay |
| 材質映射、武器位置／FOV、動作與模型片段對應 | Object_FPS presentation |

## 資產分析

來源為 `assets/object_fps/model/mark-23/source/Mark23.fbx`：FBX 7500，
4 個網格（Hand_Mesh、Side、main、mag）、53 個 limb 節點、49 個 skin
clusters、4,131 個控制頂點與三角化後 7,762 個三角形。
控制頂點數不等於 GPU 頂點數；UV 接縫與材質分組會拆點。

| 動畫 | 30 fps 原始範圍 | 秒數／用途 |
|---|---|---|
| Reload | 1–113 | 112/30，換彈 |
| Shoot | 113–123 | 10/30，射擊 |
| Hide | 123–134 | 11/30，收槍 |
| Draw | 135–160 | 25/30，拔槍 |
| Idle | 160–161 | 1/30；取起始持槍姿勢並保持 |

Draw 是拔槍動作，持槍姿勢由 Idle 提供。匯入保留各片段長度，並把
原始非零時間起點轉為片段局部零點。以 ufbx 的烘焙功能處理 Euler
曲線、pivot 與 pre/post rotation，再輸出中立 TRS 軌道。

手臂最多有四個骨骼影響；部分權重和約為 0.999013，需要正規化。
骨骼權重超出四個、非法索引或不合法動畫資料會回報錯誤。
共享 ModelAsset 不保存播放器時鐘或 GPU handles；實例各自持有姿勢
與可重用的蒙皮緩衝。

材質 `Hand_D`、`Glove_D`、`Mark23_D` 分別對應提供的三張 PNG。
手臂有兩個材質槽，合計五組 mesh submissions。貼圖都經 AssetId
取得；FBX 中作者的舊絕對路徑不會被開啟。四張引用的法線／高光
貼圖未附上，因此本輪沿用 unlit 底色渲染，不加入 PBR。

槍身三個網格的原始 UV 並不限於 0–1：V 約為 1.00–2.00，main／mag
的 U 最大約 1.31。FBX 材質使用 Repeat；匯入器只轉換為左上原點的
`(u, 1-v)`，保留越界座標。presentation 的 `sampler: linear_wrap`
確保貼圖正確重複；不能逐頂點取餘數，否則會破壞跨邊界三角形的插值。
首次 GPU 擷取揭露的灰色條紋即來自 Clamp，已修正並補回歸測試。

## 跳躍與武器規則

- 玩家腳底 `feetY` 是位置真值；camera Y = feetY + eyeHeight。
  受擊膠囊、射擊起點與敵人瞄準都使用同一個高度。
- Space 按下且接地時起跳。高度 0.6 m，重力 18 m/s²，起跳速度
  sqrt(2gh)。以常加速度解析式積分，落地清零垂直速度；長按不連跳。
- 空中維持既有水平移動與格子牆／敵人阻擋，沒有牆頂落地或斜坡。
  近戰也檢查垂直距離，遠程攻擊瞄準離地後的膠囊中心。
- 新戰役從 Draw 開始。左鍵射擊、R 換彈、H 收槍／拔槍。
  Idle／Shoot 的同幀優先序是 H、R、左鍵；Reload／Draw／Hide
  不可中斷、不排隊，完成幀不再處理新指令。
- 原速射擊間隔 10/30 s、換彈 112/30 s；12 發彈匣、48 備彈、
  25 傷害。射擊開始即扣彈與解析命中，換彈完成才轉移備彈。
- WeaponPresentationSnapshot 記錄 action、elapsed、duration、revision。
  相同 snapshot 重繪產生相同姿勢；GPU 不決定補彈或動作完成。
- 暫停／過場凍結動作與跳躍。換關卡重設腳底位置並清後座力，
  保留武器動作進度與彈藥；新戰役才重設武器。

## 視角與繪製順序

`mark23_viewmodel.json` 保存 model/material/clip IDs、anchor_node、
offset_meters、rotation_degrees、scale、vertical_fov_degrees 和裁切面。
以 Idle 的 main_j 作固定基準；不依每個動畫姿勢重新置中。
所有值都是遊戲 presentation 設定，不進入通用 Model 或 Render。

經 960×720、1280×720、1680×720 的 GPU 影格校準後，採用：

| 參數 | 最終值 |
|---|---|
| Idle 定位節點 | `main_j` |
| offset_meters | `(0.12, -0.18, 0.55)` |
| rotation_degrees | `(0, 180, 0)` |
| scale | `1` |
| vertical_fov_degrees | `55` |
| near_clip / far_clip | `0.01 / 5` m |
| sampler | `linear_wrap` |

相較最初 `(0.16, -0.18, 0.45)`，稍向左與前方移動，讓 4:3 換彈時
槍身和彈匣保留在畫面內。持槍時準星中心區域保持清楚，手臂從底部延伸。
Hide 結束／Draw 開始位於畫面外是原始動作的預期結果。

繪製順序為 World／Scene sprites → ViewModel → exposure/gamma → HUD。
ViewModel 載入已畫好的 scene color，重新清除 depth，因此靠牆不會
遮住槍；槍、滑套、彈匣與手臂仍互相深度測試。
CPU 蒙皮後只更新相同 mesh 的 vertices，indices 與 handle 保持不變。
後端循環使用 GPU／staging buffers，避免覆寫前一幀仍在讀取的資料。

本次亦修正既有 SDL_GPU 的正反面判定：GYO 的 +Z 左手投影下，朝外面
投影到 render target 的正面為 Clockwise。先前使用 CounterClockwise
會剔除手指／槍械外表面、顯示內部，造成可看穿手指的現象；天空內側也
受影響。ufbx 已處理座標反射時的索引反轉，不再對匯入結果翻面。
武器保留單面剔除與深度寫入，並以單面外殼及天空內側 GPU 像素測試防回歸。

命中保持世界空間的 camera aim ray 與 muzzle-to-aim 遮擋查詢。
武器視角的構圖參數不改變碰撞或傷害。

## 共用門貼圖與部署

`assets/common/asset_catalog.json` 登錄 `common.texture.white`，實際來源是
本次新增的 `white1x1.png`。門使用獨立已載入的 texture handle。
AssetCatalog::AppendFromFile 先完成解析／路徑／重複 ID 驗證再合併，
失敗不留下部分新增資料；common 與 game 各有自己的資產根目錄。

打包同時複製 `assets/common` 與 `assets/object_fps`。偵測到部署版
game catalog 後，所有資產從同一部署包取得；缺少 common 時直接報錯，
不允許 `../` 逃逸，也不以源碼資產掩蓋部署缺漏。
`object_fps_assets` 是遊戲建置的固定依賴，每次建置都同步兩個目錄；
單獨修改 JSON 或貼圖也能更新部署內容，不依賴 executable 重新連結。

## 驗證方式

- `object_fps.headless`：角色、武器、離地受擊、snapshot 與模型提交。
- Model unit tests 與真實 FBX regression：五段動畫起點／中段／終點
  對照 ufbx 評估結果，包含滑套、彈匣、綁定姿勢與權重。
- Render queue tests 與 `render.sdl_gpu_mesh_smoke`：無效／過期 handles、
  頂點數限制、循環更新、ViewModel camera/depth 與提交順序。
- `object_fps.smoke`、`object_fps.menu_smoke`、
  `object_fps.viewmodel_smoke`：實際 SDL_GPU 啟動與五段動作／收起姿勢。
- 執行 `gyo_object_fps --viewmodel-preview` 可固定姿勢檢查構圖：
  1–6 切動作、左右方向鍵調進度、Space 切換離地高度、Esc 關閉。
  `--preview-4x3` 或 `--preview-21x9` 可檢查其他比例。
- 在 `--viewmodel-smoke-test` 後加 `--capture-dir <directory>`，會輸出
  六種狀態各 0／50／100% 共 18 張 BMP，驗證場景會面向白色出口門。
  後端的單次 `RequestSceneCapture`／`TakeSceneCapture` 診斷介面只在
  要求時等待 GPU readback；一般幀不等待。影像是 world／Scene／ViewModel
  完成後的 sRGB8，尚未套用曝光／Gamma 或 HUD，因此不是最終螢幕截圖。

## 本次驗收結果

- Windows／VS 18 Debug 完整建置；整合 CTest **14/14 通過**，涵蓋
  Engine、Model、FBX、Collision、Render、Input、UI、Editor 與 Object_FPS。
- FBX 測試 **7 cases / 19,828 assertions**，包含五段動畫起點／中段／終點
  與獨立 ufbx 評估蒙皮比對、滑套／彈匣、越界 UV、非法檔案、靜態網格及
  3,000 層節點階層。動作終點亦核對能連回 Idle。
- 停用遊戲、Runtime、Editor、SDL 與 FBX adapter 的獨立組合：
  Engine／Model／Collision **3/3 通過**；只啟用 FBX adapter、停用遊戲與
  SDL 的組合：Model／FBX **2/2 通過**。
- 真實 GPU 像素測試驗證近牆不遮武器、武器自身遮擋、Scene／ViewModel／
  曝光／HUD 順序，以及奇數寬度 readback。模型測試同時確認 handle 穩定。
- 獨立部署包從另一個 Object_FPS 工作目錄啟動通過；刻意不附 common
  catalog 時明確以 exit 1 報錯，補齊後完整武器 smoke 以 exit 0 結束。
- 三種比例共 **54 張** GPU 影格檢查白門、持槍、射擊、換彈、拔槍與收槍。
  使用程式輸出影格做離線檢查；桌面操作已依使用者的 Esc 停止。

本輪限制仍為 CPU 蒙皮、unlit 底色、最多四個線性骨骼影響；不支援
動畫混合、雙四元數、morph/cache deformers、PBR 或立體地形角色控制。
