## 問題、設計與實作

移動 ACK 可包含替代步，movementEpoch 可以重設，Network Snapshot 可以合併。
三者都不能代替「同一次動作的終局答案」。本批以獨立 ActionId 帳本保留原請求及
裁決，來源仍歸 Match；各層都有界交接，直到 Client 消費後形成連續 ACK 才退休。

| 位置 | 完成的責任 |
|---|---|
| `protocol/client_v4.proto`／`runtime_v4.proto` | 獨立 schema，新增規則、shot、decision、combat；不共用遊戲 schema |
| `protocol/clientv4/`／`runtimev4/` | Go 生成 bindings，移除舊 v3 版本；C++ 生成於 build tree |
| `ClientConnection.hpp/.cpp`、`Wire.hpp` | 有界 ID 配置、不可變重送、保留裁決、Drain 交付後的連續 ACK |
| `gateway/action_delivery.go`、`runtime_link.go`、adapter | Session → PlayerId、原子驗證、32 ID 窗口、循環八筆重送 |
| `PvpMatch`、`MatchRuntimeHost` | shots＋ACK 原子接納，預留容量；世界修改與退休仍在 Tick |
| `IpcHost.cpp` | v4 codec、Match 規則來源、獨立結果 lane、部分 TCP frame 完整寫出 |
| 產品專屬 acceptance／tests | worker、wire、Go race、真 socket 動作 probe 及證據分析器 |

- **ACK 與 shot 同批原子生效。** 先驗證原紀錄是否衝突，再計算有效 ACK 所能釋放的
  容量；不能先 ACK 回收再發現衝突。有效待交付 ACK 可預留下一窗口，不必因同 Tick
  的交接先後而錯拒；真正退休與提交仍在 Tick。pure ACK 走 SubmitActionBatch。
- **帳本與快照分開。** 未開始的完整 snapshot 可 latest-wins；裁決不能只存在於
  這個 mailbox 或會丟失通知的 control queue。Match 保留原答案，Host／Gateway
  循環取最多八筆，Client 主執行緒停頓也不遺失未消費裁決。
- **確認代表交付責任。** Client Drain 將 owning decisions 交給遊戲一次；只有已
  交付的連續 ID 才 ACK。未消費結果仍佔本機容量，Gateway 不因「已轉送」自行確認。
  ID 數量及距退休下界皆 ≤32；退休前重送相同 ID，不能逾時換 ID 補開。
- **排程不追補過期次數。** shot／ACK 共用最多 30 Hz；結果亦最多 30 Hz。阻塞
  測試暴露 Gateway 使用排隊的 ticker 時間，以及 frame 等候其他寫入後沿用舊
  deadline 的邊界；已改以現在時間檢查，並於實際寫完後重新錨定。移動原排程不改。
- **生命週期隔離。** movementEpoch、history overflow、未 Drain 都保留動作；
  Leave／斷線／換 Session 才清理。已接收 frame 不能跨新連線 generation 復活。
- **規則單一來源。** Ready／Welcome 傳送 Match 的 PvpCombatRules；Client／Go
  做格式與範圍驗證，不另維護權威傷害或冷卻預設。HP／冷卻是最新 combat 集合，
  不插值、不被移動重播覆寫。

schema 使用 build 的 protoc 36.2 與產品 module 固定的 protoc-gen-go v1.36.11。
UDP 類型新增 Actions=6／ActionResults=7；24-byte header 及完整 1,200-byte 上限
不變。公共 Session 固定一秒合計 120 包上限也不變，計入 Hello、重送及無效的
已認證流量；產品 Gateway 只增加實際限流計數的唯讀診斷。

### 動作矩陣與移動共存

16 案涵蓋：乾淨 baseline、首 shot／結果／ACK 遺失、重複／亂序／衝突／非法包、
未 Drain 1.3 秒，以及 upstream、downstream、socket-path、Gateway、Host IPC
各 250 ms／1 秒阻塞。測試控制只在 probe，不加入正式遊戲。

全部 **4,724 筆唯一動作取得、消費並退休原裁決**；逐快照、依裁決 Tick 核對
**23,040 筆 HP 觀測**，符合唯一動作效果，避免最終 HP 歸零掩蓋重複扣血。
重送原答案不變；舊時間參考依法終局拒絕，不保證過期射擊補開。

乾淨 baseline 固定去掉首一秒暖機與末一秒排空，未過濾慢幀；同機射擊壓力下：

| 指標 | 實測 | 原門檻 |
|---|---:|---:|
| 移動命令產生 | 每玩家 240，合計 480，60 Hz | 60 Hz |
| 原命令 Actual 比例 | 100% | ≥99% |
| 首次成功送出 P95 | 16.21 ms | ≤22 ms |
| Actual 執行 P50／P95 | 45.79／45.86 ms | ≤50／66.7 ms |
| epoch 重設／runtime gap | 0／0 | 乾淨跑次不得隱藏干擾 |
| 所有認證流量一秒最高 | 91 包 | ≤120 |

動作／ACK 所有案例最高 30 包／秒，結果最高 23 包／秒；注入非法／重複流量後
Client 發出的一秒窗口最高 94 包。每玩家窗口最多 32，收尾全部回到零。

### 保留的失敗與限流解讀

刻意 SIGSTOP Gateway 一秒會在 OS／傳輸路徑積存封包，恢復後到達固定窗口。
該案實際接受窗口最高 120，**118 包被既有限流拒絕**，所有動作仍取得原裁決並
退休；新裁決最慢 332.35 ms，移動 Actual 在 82.36 ms 恢復，349.02 ms 已證明
穩定。正常共存與其餘故障零限流拒絕。

初版分析器將「所有故障零限流拒絕」當成要求，因此原始 action-matrix.json／
該案 result.json 為失敗並保留。這比計畫的「正常共存不超限流；有效 Session
故障解除後有界恢復」多了一項假設。最終分析只允許刻意暫停 Gateway 的案例記錄
實際拒絕，仍強制接受上限 120、所有原裁決／HP 一致性及 1.5 秒恢復；沒有提高
上限、增加射擊預算、刪除慢樣本或放寬恢復門檻。

分析器最後增加回歸，確認正常流量有拒絕、接受數 121、缺少實際故障起訖證據都
必須失敗。最終重核另寫 result-final.json／action-matrix-final.json，保留原始
結論與錯誤，不覆寫原 trace。早期未完成矩陣不作本批完成證據。

### 既有移動與生命週期

另跑原有網路 acceptance：乾淨雙 Client 取得 241 份一致權威快照；RTT 0／20／
40 ms、設定單向抖動最多 10 ms、5% 丟包、首包及連兩包遺失三案皆完整覆蓋。
包含停止／恢復、timeout、worker 存活而主執行緒停頓六秒、重入新身分／Lobby
人數、取消加入、Leave 失敗清理屏障、destructor 清理，以及 IPC 失敗兩端回 Lobby。
替代 Gateway 可加入清場後的 Match；畸形 IPC 不令 Match 崩潰。

這是短故障注入；六秒停頓不是長時間穩定性測試。代理暫停路徑／部分 TCP header
驗證不等於 kernel socket buffer 飽和，報告明確標記未證明該項。

## Architecture Delta、限制與交接

1. Feature 壓力：射擊需獨立身分、期限、終局裁決及消費確認；移動 ACK／快照不足。
2. 改變的邊界：產品 Client／Host／Gateway API 及兩份線上契約一起升 v4。
3. 影響：產品 C++、Go Adapter／Gateway、schema／bindings、產品 source／acceptance
   CMake；新增 action probe role 仍在既有 owner 登記。沒有公共 build 專用分支。
4. 依賴／Ownership：仍全部歸 object_fps_pvp，Engine 與公共 services 無修改，
   沒有新 Top-level subsystem 或產品間依賴。Match 動態依賴只有標準執行庫，無 SDL。
5. 更小修改不足：單個 fire bool、瞬時通知或快照欄位無法保存不可重複的原裁決。
   採局部 schema／既有介面擴充，不建立全產品可靠訊息框架。
6. Fitness：新增內容與引用均在 owner 邊界，專屬測試依產品選取；活動來源無 v3
   bindings 引用。未重跑完整刪除副本建置，不把靜態檢查宣稱成完整移除驗收。

沒有執行 shader／GPU／GUI 射擊、實體 LAN、Windows 或長測。歷史 v3 release
manifest 未覆寫，新的來源／產物不能冒用既有長測認證。OS 拖窗整機停頓根因仍未
證實。本批沒有待決的契約變更；第 04 批才接本機武器回饋、輸入與 HUD。
