## 02a：舊驗收模式移除與版本常數

### 停止與重新決定（D14）

計畫依 D11④「附涵蓋對照表後刪除」，前提是 `weapon_short` 的涵蓋已由動作短測取代。開工盤點後發現這個前提只有一部分成立：
只有觀察方的「HP=0 仍可移動與射擊」是 v4 語意，其餘多數斷言別處沒有涵蓋。依停止條件停下回報後，
使用者決定：**把獨有斷言移進 `action_short`，再刪除 `weapon_short`**（D14）。

### `weapon_short` 涵蓋對照表

| `weapon_short` 的斷言 | 處置 |
|---|---|
| 觀察方 HP=0 仍可移動、射擊（v4 語意） | 刪除；v5 的死亡抑制由 `action_short` 的 `dead-click`／`dead-move`／`dead-stop` 涵蓋 |
| 擷取點擊不產生射擊 | `action_short` 既有 `capture` |
| 按住射擊只出一發、一次動畫 | `action_short` 既有 `held_fire_one_shot` |
| 本機射擊回饋出現在首個成功 Presented 幀，且早於權威裁決 | 移入：每發射擊檢查，`local_feedback_before_decision` |
| 射擊到首個 Presented 的時間 | 移入：逐發記錄 `submission_to_presented_seconds`；分析器要求筆數等於射擊數、值有限且 ≥0 |
| 明確注入第二發，權威回 Cooldown 拒絕 | 移入：在 `held-shot` 後注入，`authority_cooldown_wall_and_hit` |
| 打牆得到 World 判定、命中標記、命中次數 | 移入：同上（打牆 11 發、擊殺 4 發） |
| 移動＋轉向＋射擊同一幀，滑鼠位移只消耗一次 | 移入：第一發打牆改為 `combined-wall-shot`，`movement_turn_shoot_mouse_once` |
| 下一幀不重播滑鼠位移 | 移入：`mouse_delta_not_replayed` |
| 失焦、失焦中按住、Tab、拖動視窗：不產生射擊並釋放擷取 | 移入：`focus-loss`／`focus-gain-held`／`tab-release`／`drag`，檢查不配發 ID 且擷取已釋放 |
| ESC 清空武器狀態 | 移入：`escape_clears_weapon` |
| 重新加入時滿血、沒有殘留射擊或裁決 | 移入：`rejoin_full_hp_no_stale_effects`（另加彈匣全滿） |
| ESC 前 ID 數＝SDL 送出數＋1 次注入 | 移入：`escape` 事件的檢查 |
| 存活時每個 Presented 幀都提交第一人稱武器 mesh 與材質 | 移入：逐幀檢查 |
| 第一人稱 GPU capture：draw／shoot／resize／wall-depth | 移入 `action-capture`：攻擊方 8 張（原 4 張＋這 4 張），觀察方 4 張 |
| `run_weapon_short.py` 的 `latency` 案例 | 刪除；`run_timing.py --gui --short` 跑同一個 `--latency-short` 模式，並有自己的視窗干擾閘門測試 |
| `weapon_result` 的平均 FPS ≥ 名義×0.85 | 刪除；屬第 8 項的計時假設，不搬到新位置 |

時程：攻擊方的動作排在原本的 v5 動作之後（10.2 秒起依序是視窗互動、resize、走向牆邊 2 秒、ESC 與重新加入），
ESC 排在目標重生被呈現之後。預設長度由 15 秒改為 18 秒，範圍 18～25 秒。

### 第 6 項需要的逐幀欄位

- `action_short` 的每個 Presented 幀記錄 `presented_weapon`（`active`、`dead`、`life`、`submitted_meshes`、`shooting`、`last_action`）。
  選 `action_short` 而不是 `player_short` 的理由：它已經有本機死亡與重生的時程。
- 分析器（`run_action_short.py`）：本機死亡且某個 Presented 幀的 `submitted_meshes>0` 判失敗。突變測試：`test_dead_local_player_presenting_weapon_meshes_fails`。
- 限制（照計畫）：產品在 `!Alive()` 時直接把這個欄位設為 0，所以它抓不到不經 `SubmitWeapon` 的殘留畫面；第 05 批要另訂觀測量。

### legal 模式涵蓋對照表

`run_action_legal.py`、probe 的 `--legal-shots`、`action_evidence.analyze_legal` 都刪除。
`analyze_legal` 的檢查在 v5 長測分析器 `gameplay_soak_evidence.py` 中的對應：

| `analyze_legal` | `gameplay_soak_evidence` |
|---|---|
| 原始送出不重複、裁決不重複、裁決都有對應送出、沒有遺漏 | 重複送出、重複裁決、遺漏預宣告動作、終局裁決不符 |
| 量測窗口與宣告長度一致 | 預宣告的循環分母、probe 在宣告結束前停止 |
| 射擊間隔 ≥400 ms（v4 定速規則） | v5 以預宣告計畫與 10 Tick 冷卻取代：裁決必須與計畫一致 |
| 接受與拒絕碼一致、拒絕不造成傷害、傷害歸屬 | 同名檢查 |
| 每位玩家都有實際 HP 下降 | 每個循環的預宣告致命命中恰好傷害該生命一次 |
| 裁決有 Match Tick、產生到裁決 P95 ≤100 ms、到 Client P95 ≤150 ms | 同門檻 |
| 幀時間單調、每幀 HP 與已知效果一致 | 幀時間單調、權威 HP／彈藥／換彈與逐生命效果一致 |
| 送出數＝裁決數＝退休數、批次 ≤8、datagram ≤1200 | 動作 ID 連續並跨生命退休、批次與 datagram 上限 |
| 移動與動作窗口上限 | 有界命令／動作窗口 |
| 乾淨跑次沒有 ≥100 ms 間隔、沒有凍結、移動證據通過 | 全程 ≥100 ms 幀、Match 掉時、移動 Actual 門檻與 ≥99% |

`action_probe.py` 的 `network*`／`burst2` 原本靠 `--legal-shots` 在非 gameplay 模式運作。現在改為明確報錯並指向 `run_gameplay.py`；
v5 的 25 案矩陣一直是經 `run_gameplay.py`（`--gameplay-v5`）執行，不受影響。
