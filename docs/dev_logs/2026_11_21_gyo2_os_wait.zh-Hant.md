# 2026-11-21 core/time 的等待改呼叫 core/os（v8-arch-gyo2-os-wait）

Owner：架構（GYO2 主會話「[GYO2][不良少年]新架構重構」開出的任務卡）。分支 `claude/gyo2-os-wait-4a65a6`，從 `gyo2` 2acf9cee（含 #261）。
事前宣告：[`os-wait-declaration.zh-Hant.md`](../architecture/target/v2/os-wait-declaration.zh-Hant.md)（修訂 3；使用者 2026-11-21 動工前核准「照建議，全部核准，開始」）。

## 為什麼

- 使用者 2026-11-21：「os是底層兼容層，對外也只是提供一個介面（否則就沒有意義了）。需要調用OS能力的時候，就去調用os介面就好了。不需要碰底層OS api」；「開os卡，先查 W3 的原因。再做core/os，完畢之後，讓time直接調用core/os的api」。
- `engine/core/time/src/Waiter.cpp` 直接 include kqueue／Win32 標頭、依 OS 分支、呼叫 OS API，掛在 OS 邊界的准許清單上（R1 3、R2 6、R3 10），D78 時被凍結。這一批以使用者的 owner 決定取代那個凍結（宣告 §5 第 1 項、§9 的決定 2）。

## 第 1 步：W3

結論寫在宣告第 2 節：搬移沒有改到平台呼叫（H1），已知成本解釋不了 0.023 ms（H2），位移可能是真的（H3），當時的判定在 Windows 上校準不足（H4），原因未查明。修訂 3 加的 H6：A、B 用的 SDL `release-3.4.0` 一初始化就呼叫 `timeBeginPeriod(1)`，只有 window 情境載入 SDL，而 Windows 11 依視窗是否被遮住決定給不給高解析度；W3 沒記錄這些狀態，無法回頭驗證。使用者選 (a)：照純搬移寫宣告，以 L1、守衛、突變取代 D71 的計時驗收（宣告 5.4）。

## 做了什麼

- `engine/core/os`：
  - 公開標頭 `include/engine/os/WakeSignal.hpp`：`WakeSignal`（`Create`、`Signal`、`Block`、`Mechanism`）與 `WaitMechanism`。`Block` 不收 latch。
  - `src/macos/WakeSignal.cpp`（kqueue）、`src/windows/WakeSignal.cpp`（auto-reset event＋高解析度 waitable timer，退回一般 timer）：平台呼叫照舊 `Waiter.cpp` 逐行搬來。
  - `src/linux/WakeSignal.cpp`：condition variable＋自己的 pending 旗標（新的邏輯）。`Signal` 在 mutex 內設旗標；`Block` 在 mutex 內看旗標，每一條返回路徑都清掉。CMake 的 `else()`（Linux 與其他平台）選它。
  - `CMakeLists.txt`：依平台選三個來源之一；註解補上 cv 後備也用 `Threads::Threads`。
- `engine/core/time`：
  - `Waiter.cpp` 不再 include OS 標頭、不再分支；`Waiter::Impl` 以值持有 `Os::WakeSignal`，latch 仍是 Time 的。`Backend()` 由 `ToBackend(Mechanism())` 對應（`static_assert` 值對值）。`Create` 失敗時 detail 由 `Base::CauseDetail` 帶 os 的錯誤（★）。
  - `CMakeLists.txt`：保留 `target_link_libraries(gyo_time PUBLIC GYO::Base)`，加 `PRIVATE GYO::Os`，拿掉 `Threads::Threads` 與 `find_package(Threads)`。
- 測試：
  - `tests/common/os/WakeSignalTests.cpp`（新）：平台機制、先送的訊號留著、取走後不再結束下一次 `Block`、另一條執行緒叫醒、逾時（上下界）、競爭測試（每一輪先取走上一輪留下的 pending）、moved-from。
  - `gyo_os_wake_fallback_tests`（CTest `os.wake_fallback`，非 Windows）：同一組測試直接編 `src/linux/WakeSignal.cpp`，不連 `gyo_os`。
  - `OsHeaderHygieneTests.cpp` include 新標頭。
  - `WaiterTests.cpp`：「Time Waiter uses the platform backend」改成「Time Waiter reports the os mechanism」（不分 OS）。`gyo_time_tests`、`gyo_time_wake_record` 直接連 `Threads::Threads`。
  - `tests/common/time/CMakeLists.txt`：`gyo_expect_links(gyo_time GYO::Base GYO::Os)`，並拒絕 `GYO::Os` 出現在 `gyo_time` 的 INTERFACE。
- 准許清單：刪掉 `Waiter.cpp` 的三行與 `WaiterTests.cpp R2 2`。
- 文件：`os.md`（Components 的 Wait 列與表下說明、Contracts 加 Wait、Invariant 3、6、8、Guard 段、RC2、RC9）、`time.md`（開頭、依賴圖、Contracts、Baselines 的 Windows 列、Invariant 5、7、8、10、RC3）、`docs/architecture.md` 的 `GYO::Time` 列、v2 README 的兩列。條文文字照兩段式，合併前交使用者定案。

## 範圍的限界（宣告 §7）

- macOS Intel：同一個形狀量過，12／12 通過（os-subsystem w6-l2）。
- Windows：同一個形狀量過（W3），window deadline P50 +0.023 ms，超出當時邊界 0.0032 ms，不通過照原樣保留，原因未查明。
- Linux：晚醒從來沒有量過（D78 取消）。macOS arm64：從來沒有量過。
- Windows 的機制選錯、旗標抄錯：L1 抓不到，只靠機械式對照的記號清單；Windows 上沒有跑突變。
- window 情境在 gyo2 上無法量（沒有 SDL）。重量時記錄 Windows 版本、視窗狀態、實際生效的計時器解析度（H6）。
