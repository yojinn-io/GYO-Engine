# PvP v4 第 02 批：權威射擊核心與動作帳本

日期：2026-09-28。結果：**第 02 批完成並停止；未開始第 03–05 批，未執行長測。**

## 授權、問題與成果

依使用者指定的 [第 02 批計畫](../object_fps_pvp/plans/v4/02-authoritative-shooting-core.md)
及 [v4 契約](../object_fps_pvp/protocol-v4.zh-Hant.md) 實作普通產品 C++ 核心。
移動確認可以包含 Held／Neutral，movementEpoch 會重設，而快照可被新狀態取代；
因此不能用移動序號或一幀快照作為「這一槍是否執行」的紀錄。

本批建立獨立且有界的動作帳本：先原子接納並保留結果空間，再於權威 Tick 裁決，
原答案持續保留至不跨洞的連續 ACK。沒有將這套 FPS 政策放入 Engine 或公共 Gateway。

實際 `.proto`、bindings、HTTP join、Ready／Welcome 仍為 **v3**。射擊目前只能由
產品 API／單測驅動；沒有 socket 射擊、GUI 開槍或 Mark23 接入。既有移動參數、
預測與重設政策沒有調整。

## 實作與設計原因

| 位置 | 本批責任 |
|---|---|
| `apps/object_fps_pvp/include/RetroFPS/Pvp/Combat.hpp` | 集中 CombatRules、請求、裁決、戰鬥狀態與接納結果型別 |
| `ShotQuery.hpp`／`src/Pvp/ShotQuery.cpp` | 當前權威姿態射線；Engine AABB／膠囊與產品地板阻擋 |
| `PvpMatch.hpp/.cpp` | 每玩家帳本、退休下界、冷卻／HP、移動完成後的穩定裁決順序 |
| `MatchRuntimeHost.hpp/.cpp` | 有界動作／ACK 交接、發布時間索引、裁決時提供可信年齡 |
| `tests/object_fps_pvp/CombatTests.cpp` | 11 個 domain 確定性案例 |
| `tests/object_fps_pvp/CombatHostTests.cpp` | 10 個 Host 時間／交接案例 |
| `tests/object_fps_pvp/ShotQueryTests.cpp` | 8 個幾何案例 |

`PvpCombatRules` 是產品預設的單一來源：100 HP、25 傷害、20 Tick 冷卻、100 單位
射程、含邊界的 250 ms 有效期。後續 Ready／Welcome 須從此來源轉換；本批不預占
wire 欄位。無散布、爆頭、彈匣、死亡或重生流程。

- **先移動再射擊**：完成所有玩家的移動後，按首次交付 Match 的 Tick、PlayerId、
  ActionId 裁決。缺少較早 ID 不阻塞射擊；同 Tick 多槍受冷卻限制，沒有補開歷史射擊。
  射線使用請求的絕對視角，不改寫移動視角。未命中仍消耗冷卻，拒絕不消耗。
- **帳本先保留容量**：pending 與未確認裁決共用最多 32 個項目，同時要求
  `R < id <= R+32`，用先比較再相減避免溢位。批次最多八筆；相同內容無操作，
  衝突或非法批次不插入任何新項目。接納失敗不是權威拒絕裁決。
- **退休不復活**：ACK 必須跨過的每一號都有終局答案，缺號／pending 都阻止退休。
  已退休請求不重做，不偽造被回收的結果；批內兩份互相衝突的退休副本仍整批拒絕。
  單份退休內容無從與歷史比較，保持無效果。
- **結果與狀態分開**：WorldSnapshot 新增獨立 combat 集合；GetActionResults
  返回 owning copy，不因讀取、快照合併、重送或時間經過而回收。movementEpoch
  只管移動，HP／冷卻／帳本／退休下界保留；Leave／Reset 才清相應生命週期。
- **發布時間不等於模擬 Tick 差**：Host 記錄每次 Advance 最終 owning snapshot
  進入 handoff 的 Tick／steady_clock 時間，最多 64 筆。catch-up 中間快照沒有
  錨點，TakeSnapshot、零步 Advance、重送不刷新時間。裁決時才讀年齡，因此
  牆鐘停頓一秒，即使只走一個模擬 Tick，舊請求仍會過期。
- **I/O 不改世界**：Host 先與 Match 帳本共同驗證 staged 窗口，到 Tick 才提交動作
  及 ACK；確認到此時才釋放窗口。結果尚未接入 IPC／Gateway，後續仍須實作可靠
  保存、批次切分與重送，不能把本批 API 視為完整網路交付。

來源時間是可替換的 Host 依賴，正式預設 steady_clock；domain 僅收可信年齡查詢，
不自行讀時鐘，不接受 Client 指定射擊位置／傷害／模擬時間。發布索引是有效期
metadata，不是命中盒歷史。單一玩家 Leave 不清除仍有效的全世界發布索引。

## 短測與建置證據

從 repository root 執行：

```bash
cmake --build build/target/_build/test \
  --target gyo_object_fps_pvp_tests gyo_object_fps_pvp-match gyo_object_fps_pvp --parallel 2
ctest --test-dir build/target/_build/test \
  -R '^object_fps_pvp\.(cpu|presentation_evidence|command_evidence|recovery_relay|backpressure_evidence)$' \
  --output-on-failure --output-junit logs/pvp-v4-batch02-cpu.xml \
  -O build/target/_build/test/logs/pvp-v4-batch02-cpu.log -V
```

三個目標建置成功。五項 CTest 全部通過，總時間 **8.25 秒**：

| 測試 | 結果 |
|---|---|
| object_fps_pvp.cpu | 96 cases／1,390,385 assertions，1.21 秒 |
| presentation_evidence | 13 通過 |
| command_evidence | 31 通過 |
| recovery_relay | 2 通過 |
| backpressure_evidence | 2 通過 |

第一次執行的 `-O` 使用 `logs/...`，CTest 將文字日誌寫入 repository root 的 logs，
已移至上列 build logs 路徑；JUnit 原本即在 build logs。此處命令已明示文字輸出位置。

最後檢查補強同一案例，確認在 movementEpoch 重設**前一 Tick**已接受的射擊，
冷卻仍限制重設邊界上的新動作；同時保留原裁決及 HP。只重建／重跑受影響的 domain：

```bash
cmake --build build/target/_build/test --target gyo_object_fps_pvp_tests --parallel 2
ctest --test-dir build/target/_build/test -R '^object_fps_pvp\.cpu$' \
  --output-on-failure --output-junit logs/pvp-v4-batch02-final-domain.xml \
  -O build/target/_build/test/logs/pvp-v4-batch02-final-domain.log -V
```

最終 **96 cases／1,390,390 assertions 全部通過，1.12 秒**。新增案例共 29 個；
既有 67 個移動／預測／呈現時間線／恢復案例保留。幾何子任務另有一次獨立短測，
8 cases／47 assertions 通過，已納入上述整合測試，沒有拿它代替整合結果。

重要反例包括：250 ms ±1 ns、未知／未發布／已淘汰／未來參考、接納後牆鐘停頓、
整批衝突、重送已接受／已拒絕的原答案、缺號仍執行但不可跨洞 ACK、窗口滿與
確認後恢復、讀取不回收、HP=0、離開重入、Reset 清錨點、epoch 保留冷卻。
移動順序測試讓兩玩家反向橫移，舊世界及只更新一位玩家的世界均會錯失射線，
只有全部移動後的姿態能命中。

本機記錄：`build/target/_build/test/logs/pvp-v4-batch02-build.log`、
`pvp-v4-batch02-cpu.{log,xml}`、`pvp-v4-batch02-final-domain.{log,xml}`。
建置過程有未修改第三方 Abseil 的整數轉換警告；本批產品程式成功編譯。

## Architecture Delta 與適用範圍

- **需求與壓力**：射擊需要獨立、不可重複的終局裁決，現有移動 ACK／可替換快照
  無法承擔。只加 fire bool 或把結果放一幀 snapshot 不能滿足已批准契約。
- **責任變化**：產品 Match 新增帳本、命中及 HP／冷卻；產品 Host 新增發布時間
  metadata 與有界動作／ACK 交接。原有責任沒有移到 Engine／公共 Gateway。
- **影響與依賴**：只擴充既有 product C++ API、source list 及 owner 專屬測試。
  使用已依賴的 GYO Collision，沒有新 target、公共 subsystem、owner 或產品間依賴。
  Engine 不反向引用產品；Client 移動預測狀態沒有混入戰鬥欄位。
- **Fitness 核對**：CMake 只新增本產品來源／測試，依賴邊不變；Match 最終 link
  command 無 SDL／Render／Campaign／app_support／client_network，ELF 動態依賴也無 SDL。
  source 與測試仍隨 owner 選取／移除，不在公共流程新增特例。此為來源／連結邊界
  核對，未另執行全產品物理刪除重建。
- **較小變更**：直接擴充 Participant 帳本與既有 Host，無通用可靠通道、歷史容器
  框架或新的時鐘 subsystem。沒有契約政策偏差。
