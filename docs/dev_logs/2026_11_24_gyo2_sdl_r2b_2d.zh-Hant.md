## 拆法

R2b 範圍大，拆成兩段（卡片照 L17 判；主會話開卡時指示「Object_Connect 的 2D 需求先做，3D（PvP）接著做」）：本段＝2D（讀相機、合成、2D 種類的實體對應、疊層、讀 `GlobalTransform`、Object_Connect 的兩件、VFX 預見）；下一段 `r2b-3d`＝3D 場景、蒙皮（GPU／CPU 在那裡判）、viewmodel 相機。

## 做了什麼

1. **`render`**：`Pass2D::viewport`（目標上的像素矩形；`clear` 清整個目標＝黑邊）；`ViewportOf`、`ClipToPixels` 量在 viewport 裡；可畫元件 `Drawables.hpp`（`Sprite`、`Shape2d`〔list／strip、作者每幀給頂點〕、`RenderLayers`、`ClearColorConfig`、`ClearColor`、`ImageRef`＝素材或作者持有的圖）；`Pipeline2d.hpp`（`ExtractedCameras`、`Extracted2dItems`、`RenderImages`、`ResolveImage`、`SpriteGeometry`、`TriangleListOf`、`Queue2d`）。依賴加 asset、image、world_asset、transform、camera（只取型別）。
2. **`sdl_gpu`**：pass 的 viewport 交給 GPU 的 viewport，裁切框量在 viewport 裡。
3. **`camera`**：可選元件 `Letterbox{width, height}`——`ComputedCamera::viewport` 是置中、等比例的最大矩形；作者的 `Camera::viewport` 不動（它進雜湊）。CM-6。
4. **`render_world`**：有 `extractFrom` 的 World 宣告 extract schedule `Extract`、插在 `Main` 之前；沒有的不宣告。
5. **編排層**：`WorldSetup::ExtractFrom()`（O-12 的描述欄位讓單位看得到）。
6. **新列**：`world_render`（來源側：登記可畫元件與清除色）、`camera_render`（渲染側：抽相機）、`sprite_render`（渲染側：抽 sprite／shape、建貼圖、每個 2D 相機一個 pass）。
7. **測試**：`render.pipeline2d`（純函式）、`render.extract`（兩個 World 的 Product）、`render.data` 的 viewport 案、`camera.module` 的 `Letterbox` 案、`orchestration.extract` 的 `ExtractFrom` 案、`sdl_gpu.pass2d` 的 viewport 與管線端到端的像素比對、`sdl_gpu.budget` 加管線的量測。
8. **突變**：render 加 `rd-`／`gp-`／`p2-`／`re-` 共 34 個、camera 加 `cm-letterbox-*` 與 `cm-hash-letterbox-empty` 6 個、orchestration 加 `or-ex-setup-product-missing`；本批改動讓 6 個舊突變的 `find` 失效，照新程式改寫（`rd-view-default-unit`、`rd-clip-none-empty`、`rd-clip-no-scale`、`cm-target-always-zero`、`g8-product-build-before-units`、`or-skeleton-after-units`）。
9. **文件**：render 頁第 1、2、5 節、新第 7 節、RD-1 改寫、RD-5～RD-7、RC-RD 4、RC-RD 5、範囲の限界；camera 頁 `Letterbox` 與 CM-6；orchestration O-12 一句。

## 卡片判的（理由在 render 頁第 7 節、camera 頁；可推翻）

| 題 | 定法 |
|---|---|
| 渲染 World 的實體對應（逐種判） | 2D 段的相機、sprite、shape 都是每幀暫時的資料（Resource），沒有渲染側實體 → 總宣告的四個衝突點在 2D 段不出現；留著的只有以圖為鍵的貼圖（`RenderImages`） |
| 讀相機的 extract 由誰登記 | 另立 `camera_render`（不放 `render_world`），KeepTool 的渲染 World 不必要求來源有相機；驗過 `[re-keeptool]` |
| 黑邊放哪 | `camera` 的 `Letterbox`（推導值的視區）；不寫作者的 `Camera::viewport`（進雜湊、視窗大小每台機器不同） |
| 頂點換算 | CPU（`Queue2d`）；2D pass 的 ABI 不變，K 的 draw list 照用；超過預算時 RC-RD 4 |
| 疊層 | 照 Bevy：第二個 2D 相機＋`RenderLayers`＋`ClearColorConfig::None`；不另立疊層管線 |
| 同 z、同 order 的先後 | 照來源實體（Bevy 不定） |
| `ClearColor` 的預設 | 不透明黑（Bevy 是深灰；固定解析度的黑邊） |
| 圖從哪個 `AssetView` 讀 | 來源的（`ExtractRes`），同一幀載好同一幀畫 |
| `Text2d` | 不在 2D 段（作者用 `text`＋自己持有的圖集＋`Shape2d`；U 或有需要的遊戲再加） |
| P22 的共通內容管線 | 2D 段沒有遊戲 shader（Object_Connect 原專案的 shader 是 KamataEngine 內建的），不觸發 |
| 幀時間的預算 | 同 R2a 的 8 ms；本機經 `Queue2d` 5.37 ms（直接組 pass 4.70 ms） |

## 和其他卡的對齊

- **Object_Connect 移植卡**（`local_f0c55417`，經主會話）：它第 3 段的單一 World＋自己組 `Pass2D` 用 R2a 就畫得出動態頂點；視窗不可縮放時不需要黑邊。R2b 之後兩條路：(A) 單一 World，要黑邊時設 `Pass2D::viewport`；(B) 兩個 World＋`Shape2d`／`Sprite`＋`Camera2d`＋`Letterbox`。選哪條是移植卡的判斷。

## 本機驗證

- macOS Intel（Metal）：`ctest -L 'cpu|gpu|shader'` 238 個中 237 個通過；`cmake.PluginSelection` 失敗是本機的離線設定（`FETCHCONTENT_FULLY_DISCONNECTED` 傳進它自己的巢狀 configure、那裡沒有原始碼的路徑），和本批無關，由 L1 看。
- 依賴的原始碼與 shader 工具從其他工作樹的建置複製到本工作樹的 `build/local-cache/`（不經網路）。
