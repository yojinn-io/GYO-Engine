## 遇到的問題

### 事前宣告的時間戳判定，對正確的實作幾乎每次都失敗（ip4b）

- **原因**：宣告以回呼自己的觀測時間為基準，漏掉了「push 開始到觀測」這段耗時。本機 400 個樣本全部失敗。
- **第 1 版提案**：改用夾住 push 的區間。xhigh 審查指出這有放寬面。
- **獨立核對**：核對者自己量測、寫了 11 個突變。結論：放寬面不對稱；第 1 版的量測被 doctest 的 `-s` 灌大；「傳錯配對已經守住」不成立。
- **定稿（D38，方案 B）**：區間判定之外，再加兩條精確等式：觀測時間等於配對的第二次讀取，換算用的就是記錄下來的配對。正確的實作 100 次 0 失敗；核對者提出、在方案 A 下存活的 7 個突變全部殺掉。

### injected 標記的範圍太寬（ip4b，xhigh 審查）

- **問題**：原本用執行緒區域的旗標。注入的 push 期間，SDL 在同一條執行緒排入的真實事件也會被標成 injected，例如 push 內跑的 live frame 造成的 RESIZED。
- **修正**：改成比對事件位址，只標 `PushInjectedEvent` 正在推的那個事件。

### watch 在別的執行緒解構有競態（ip4b，F10）

- **問題**：SDL 結束事件子系統時，不持鎖就銷毀 watcher 清單和它的鎖（`SDL_eventwatch.c:37`）。
- **修正**：Design Invariant 7 加「`EventWatch` 只在主執行緒解構」，以 `GYO_ASSERT` 加 death test 檢查（D38）。

### draft PR 的推送不跑 L1

- **現象**：推送觸發的 run 只做範圍判斷，L1 job 全部 skipped，run 本身卻顯示 success。
- **影響**：ip3d、ip3e、ip4a 的 L1 曾被誤記為成功。
- **處理**：手動觸發 #561 補跑，並在 HANDOFF、IP-3 dev_log、v7.1 記錄器加上更正。

### 並行解構的測試在 windows-x64 失敗（#561）

- **歸類**：測試自身。測試缺少「等推送執行緒開始推」的握手，執行緒啟動慢時，200 輪在第一次 push 之前就跑完了。
- **處理**：本機讓推送執行緒延後 50 ms 啟動，3／3 重現（Red）；加握手後 5／5 通過（Green）。判定不變。#562 四平台成功。

### PRIVATE 化讓 ip3b 的 header 突變改由編譯器抓到（ip4c）

- **現象**：衛生測試的 TU 沒有 SDL 的 include 路徑之後，m6a／m6b 在編譯階段就失敗，宣告的 G1／G2 訊息出不來。
- **處理**：衛生測試改連 `SDL3::Headers`（只取 include 路徑），判定不變。

## 結果

- **突變**：IP 目錄 78／78、TT 目錄 14／14 殺掉，見下面「ip4d 全跑」。突變的定義在 `docs/architecture/plans/input-and-present/scripts/mutations.json`。
- **已知缺口**：
  - m-order（節點先釋放再移除）靠 SIGSEGV 偵測，依賴配置器的行為，在 ASan 下才確定偵測。L1 沒有 ASan，記為已知限制（F11）。
  - m-path（以 `path.string()` 傳路徑）只在 Windows 上能殺，不列入本機目錄；Windows CI 由非 ASCII 檔名的測試涵蓋。
- **L1**：#562（ip3d～ip4b）、#564（ip4c），都是四平台成功。

## Architecture Delta

PLAN 的 IP-4 補充裡預告過的：

- SDL3 由 PUBLIC 改 PRIVATE。
- render 後端多了 PRIVATE SDL3。
- capture 放在 GPU 後端，Render 加錯誤碼 `FileWriteFailed`。

實作中新增、PLAN 沒有寫到的：

- Design Invariant 7 加主執行緒解構的規則；Design Invariant 3 的守衛清單補上 watch 路徑（D38）。
- `error-handling.md` 平台邊界例外條款的列舉，加上 `EventWatch` 的解構子。這只是補列舉，範圍沒有擴大。
- TT 的 `run_mutations.py` 加 `expect_build_failure`，預設行為不變。
- 只供測試用的唯讀接縫：`LastWatchClockPairForTesting`、`RegisteredEventWatchesForTesting`。
- `runtime_sdl` 冒煙測試改連 `GYO::PlatformSDLNative`；header 衛生測試改連 `SDL3::Headers`。
- 未啟用產品若直接 include SDL，重新啟用時要自己連 Native，記在 `inactive_products.md` 的 IP-4 節。
