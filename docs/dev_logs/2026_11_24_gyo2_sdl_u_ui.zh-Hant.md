## 做了什麼

1. **`ui`（函式庫）**：`gyo.ui` v1／v2 的資料型別、codec（讀經 JSON Module、驗證照 master、寫經 `Json::Writer`）、`UiDocumentLoader`（型別 `"ui"`，字型與圖片以 id 宣告引用）、`UiText`（`TextContext`＋圖集＋字型表＋排字快取）、`UiRuntime`（照 master 移植；文字經 `text` 同步排字、字形進圖集；按下文字框時游標放在按的位置）、ECS 的型別 `UiRoot`／`UiBindings`／`UiRootState`／`UiAction`（同 `render` 的可畫元件，由 `world_ui` 登記、`ui_render` 讀）。
2. **`world_ui`（來源側）**：`MapUiInput`（`PreUpdate`、`input` 的 set 之後；輸入 `Message` 依時刻合併；組字中的鍵歸輸入法；可關）、`UpdateUi`（`PreUpdate`）、`ComposeUi`（`PostUpdate`、相機之後；只在自己的意思改變時寫 `TextInputRequest`）。失敗留在 `UiRootState::failure`，System 不回錯誤。
3. **`ui_render`（渲染側）**：`ExtractUi`（extract schedule；圖集只傳變更）、`QueueUiPasses`（`PostUpdate`、`ComposeCameraPasses` 之前；每台相機一個 UI 的 `Pass2D`，排在相機槽的最後）。
4. **登記**：`config/modules.csv` 三列。依賴照 L17 微調（`ui` 加 asset、image；`world_ui` 加 window、camera、world_asset；`ui_render` 加 camera_render，text 經 ui 傳遞），理由在 ui 頁第 1 節。
5. **測試**：`ui.contract`（子 Agent：27 case，master 的 golden 與 v2 文件、每條驗證與讀取規則的反例、`pvp_lobby.json`）、`ui.runtime`（master 的 runtime 測試＋master 的 layout golden 逐 bit 一致＋焦點循環）、`ui.text_field`（master 的文字框測試）、`ui.layout`（真的字型：置中、整數像素、圖集）、`ui.world`、`ui.render`、`ui.lobby`（真的 `pvp_lobby.json`＋真的字型經 `world_asset`，鍵、點擊、組字、送出、`RenderCommands`）。
6. **突變**：`docs/architecture/target/v2/scripts/ui_mutations.json` 35 個，全部 killed（見下）。

## 卡片判的（理由在 ui 頁；可推翻）

| 題 | 定法 |
|---|---|
| `gyo.ui` 的節點模型 | 文件樹，不是實體（第 3.1 節）。進 ECS 的入口照 Bevy |
| 排在哪個座標 | 相機視區的實體像素，設計畫布 `fit`；字照倍率點陣化 |
| 點陣化在哪個 World | 來源 World（同 Bevy 的 `text_system`），渲染側只讀圖集的變更 |
| 動作 | `UiAction`（`Message`），帶根實體與元素 id |
| 鍵的對應 | `world_ui` 給預設、可關（AGENTS §1.10） |
| 組字中的 Enter | 由鍵對應那一側擋（組字中的鍵歸輸入法）；runtime 照 master「確定送出已確定的文字」 |
| `gyo.ui` 經 JSON Module 讀 | 版本不升；寫出變成一行（J-5） |

- 一開始在 runtime 加了「組字中確定不送出」，和 master 的測試（組字中確定只送出已確定的文字）衝突；這條規則屬於鍵的對應，拿掉 runtime 那一條，保留 `world_ui` 那一側。
