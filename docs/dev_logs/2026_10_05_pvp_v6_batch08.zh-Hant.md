# PvP v6 第 08 批：刪除未編譯 29 檔與孤兒資產

日期：2026-10-05。**完成**，PR [#55](https://github.com/yojinn-io/GYO-Engine/pull/55) 已合併（`5b0553a`）。分支 `claude/pvp-v6-batch08`，疊在第 06 批（[#54](https://github.com/yojinn-io/GYO-Engine/pull/54)）上。
計畫見 [第 08 批](../object_fps_pvp/plans/v6/08-remove-uncompiled.md)，紀錄見 [v6 交接](../object_fps_pvp/plans/v6/HANDOFF.md)的「第 08 批進度」。

## 開始

使用者先問這 29 檔的功能，以及做「單機劇情＋聯機選項」時能否沿用。

- 結論：這些是從單機版複製過來、從未編譯的舊單機架構（Client 自己判定），與本產品的權威 Match 架構不相容。
- 原版在 `apps/object_fps_v2`；刪除前的版本可由 commit `ccbd279` 取回。
- 單機＋聯機的建議做法：在本機執行同一套權威模擬。這記為 v7 之後的候選，詳見 HANDOFF。
- 使用者決定照計畫刪除。

## 做法

1. **程式：**
   - 刪除 29 個 `.cpp`。
   - 刪除 29 個 header：從所有已編譯來源（產品、測試、驗收 probe）沿 include 關係走不到的。
   - `sources.cmake` 只留 `PVP_DOMAIN_SOURCES`。
2. **資產：** 從程式引用的 id 出發，沿資產內容裡的 id 引用遞移。
   - 走不到的 30 個中，29 個刪除。
   - `object_fps_pvp.arena` 保留，因為以路徑載入。
   - 另刪 2 個不在 catalog 的孤兒檔案。
   - catalog 從 50 個條目減為 21 個。
   - 刪除的美術資產在 `assets/object_fps_v2` 都有逐位元相同的原版。
3. **新增產品自有的 catalog 檢查**（`tests/object_fps_pvp/test_asset_catalog.py`，CTest `object_fps_pvp.asset_catalog`，只在選擇本產品時組入）：
   - 每個條目的檔案存在；
   - 資產檔都已登錄；
   - id 不重複；
   - id 都被使用，或附理由保留。

## 驗證

- catalog 檢查 6 個測試通過；突變 3 個（孤兒 id、路徑不存在、未登錄檔案）都被抓到。
- 已編譯來源不變：重新 configure 前後的 `compile_commands.json` 同為 957 個檔案、清單相同。
- CTest 59／59。
- grep：沒有殘留引用；只剩歷史紀錄。
- 權威 digest 同機兩樹（base＝`ccbd279`，暫時的 worktree，用完已移除）：35 個情境 0 不同。
- 第 10 項的兩列結案：
  - `GroundPoint` 的有限性檢查與格子線段檢查都在被刪的檔案中；
  - 敵人攻擊時間容差不一致的兩處也都被刪除。

## Architecture

- 只刪除產品內容與產品登錄資料，不改共通 Build、Packaging、Workflow。
- 新的檢查屬產品自有（`tests/object_fps_pvp`）。
