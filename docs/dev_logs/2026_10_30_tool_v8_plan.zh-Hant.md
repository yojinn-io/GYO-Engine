- 為 `v8-tool-ui-editor-widgets`、`v8-tool-voxel-map-editor`、`v8-tool-assets-editor` 寫出需求、Data Contract、owner 與依賴方向、手動／Script 階段、分批（檔位＋引擎＋估時）、驗收。
- 建議順序 ui → voxel → assets，並列出 18 項等使用者決定的事。

## 經過與證據

1. 輸入法：`engine/input/backend/sdl/src/SdlInput.cpp:316-334` 只處理 `SDL_EVENT_TEXT_INPUT`；全 repo 找不到 `TEXT_EDITING`、`SetTextInputArea`。組字中的字不會到產品，畫面也不顯示。「:」卡住仍未重現，所以第一批排檢測（`v8-tool-ui-ime-observe`），不排修正。
2. UI：`gyo.ui` v1 的元素集合是封閉的，沒有輸入框（`docs/ui_toolchain.md`「JSON v1」）；大廳的位址欄是一顆 `button`，編輯在 `PvpApplication.cpp:195-260` 手寫。`UiInputFrame`（`UiTypes.hpp:129`）沒有文字。`GYO::Ui` 與 ui_editor 沒有 `Design Invariants` 節。
3. 地圖：arena v1 是 AABB 牆清單（`Arena.hpp`）；protocol-v6 第 51 行把「`Arena` 新增成員」算成 wire 變更。所以建議地圖編輯器的原始檔烘焙成 arena v1，不讓執行端讀格子。
4. 3D 視窗：共通 Build 的 `IMGUI` 只對應 `imgui::sdl3_sdlrenderer3`（`GyoAppProject.cmake:131`），voxel 與 assets 都需要 SDL_GPU 版的後端。
5. hitbox：先例是 v2 的 `hurt_regions`；格式與 owner 交給 `v8-product-hitbox-data` 決定，工具線只列對齊事項。
