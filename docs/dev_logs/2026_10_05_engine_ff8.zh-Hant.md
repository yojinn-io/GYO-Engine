# Engine FF-8：GYOP 標頭 C++ 編解碼收進 Engine

日期：2026-10-05。**完成**，PR [#45](https://github.com/yojinn-io/GYO-Engine/pull/45) 已合併（`745590b`）。分支 `claude/engine-ff8`，疊在 FF-3 上。
計畫見 [基礎後續整理 PLAN 的 FF-8 節](../architecture/plans/foundation-followups/PLAN.md)。

## 開始與檔位

接續使用者「把 Engine 側的功能完成」的指示。檔位 high。計畫建議「解碼拒絕條件局部 xhigh」；xhigh 高於主對話檔位，使用者不在，無法依 D8 徵求同意，所以沒有升檔。
補強方式：先鎖住舊行為（完整拒絕表），再以突變確認每一條傳輸檢查都有測試抓得到。

## 做法

1. **先鎖舊行為**（`tests/object_fps_pvp/WireTests.cpp`，在舊的 `Wire.hpp` 上通過後才動實作）：
   - 7 種訊息的編碼逐位元（期望值以 Python `struct` 另行計算）與 decode 往返。
   - 完整拒絕表：長度 0／1／23、length 欄位比實際多或少、magic、版本 4／6／0x0105、@22／@23 非 0、Type 0／8／0x0103；Type 1～7 接受；剛好 1200 bytes 接受、1201 bytes（length 欄位一致）拒絕。
   - 超過 1200 bytes 的編碼丟 `std::length_error`。
2. **Engine 子系統** `engine/net`（target `gyo_net`、alias `GYO::Net`，只依賴 `GYO::Base`）：
   - `engine/net/GyopDatagram.hpp`：`GyopHeaderSize`、`GyopMaxDatagram`（1200，Engine 傳輸契約，呼叫端可更小、不可更大）、`GyopHeader`（@22 依 Go 命名為 `channel`，v1 只有 0）、`EncodeGyopDatagram`、`DecodeGyopDatagram`。
   - 錯誤以 `Base::Result<…, NetError>` 回傳（`MalformedDatagram`、`DatagramTooLarge`、`UnsupportedChannel`），依錯誤處理契約。
   - 解碼只檢查傳輸條件；版本與 Type 交給呼叫端（有測試證明任何版本與 Type 都原樣通過）。
   - include 暫用 `engine/net/`（與 base、input 相同），由 FF-7 統一。
3. **共用合成向量** `tests/common/net/fixtures/gyop_datagram_vectors.json`（Python `struct` 產生）：4 個有效、10 個 malformed、2 個 encode 拒絕。
   C++ `tests/common/net/GyopDatagramTests.cpp`（`gyo_net_tests`，標籤 cpu）與 Go `services/gyo_gateway/framing/vectors_test.go` 讀同一份。
4. **消費端改用**：`Wire.hpp` 的 `Encode`／`Decode` 包裝 Engine；`wire::ProtocolVersion`＝5 成為唯一的版本常數；Type 範圍 1～7、`Read`／`Write`、`Newer`、TCP `Frame` 留在產品。`ipc` 與 `client_network` 公開連結 `GYO::Net`。

## 拒絕條件對照

| 條件 | 改動前（產品 `Wire.hpp`） | 改動後 |
|---|---|---|
| 短於 24 bytes | 產品拒絕 | Engine 拒絕（`MalformedDatagram`） |
| 長於 1200 bytes | 產品拒絕 | Engine 拒絕 |
| magic 不是 `GYOP` | 產品拒絕 | Engine 拒絕 |
| @22 非 0 | 產品拒絕（當 reserved） | Engine 拒絕（Channel 非 0） |
| length 欄位與實際不同 | 產品拒絕 | Engine 拒絕 |
| 版本不是 5 | 產品拒絕 | 產品拒絕（`ProtocolVersion`） |
| Type 不在 1～7 | 產品拒絕 | 產品拒絕 |

組合後的整體行為以 `WireTests.cpp` 的拒絕表證明不變（改動前後都通過）。

## Architecture Delta（新增 Subsystem，依 AGENTS §3）

1. 需求：D4（GYOP 標頭 C++ 編解碼收進 Engine），在消費端協議升版批之前。
2. 問題：Engine 的傳輸契約，C++ 實作只在產品內並寫死版本；Go 與 C++ 沒有共同向量。
3. 邊界：新增 Engine 子系統 `engine/net`（單一 target `gyo_net`），不是新的 Top-level Directory。
4. 影響：Engine（新 target）、消費端 `Wire.hpp` 與兩個 library 的連結、`services/gyo_gateway/framing` 的測試、tests/common。
5. 依賴方向：新增 `gyo_net→GYO::Base`，以及消費端 `ipc`／`client_network`→`GYO::Net`；Engine 不依賴任何產品。
6. Ownership：標頭編解碼與 1200 bytes 上限歸 Engine；版本、訊息種類、Type 範圍、payload、TCP frame 歸產品。
7. 更小的替代：見計畫（使用者已決定 D4）。

Fitness：刪除消費端後，`gyo_net`、`gyo_net_tests` 與共用向量仍成立；Go 測試也只依賴 tests/common 的合成向量。
